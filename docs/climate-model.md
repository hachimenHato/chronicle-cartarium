# 气温、降水与生态图层说明

更新：2026-10-16。本说明对应 `src/lib/geography-climate.ts`、`src/lib/geography-fields.ts`、`src/lib/thematic-colors.ts` 和星球环境预览。本轮只读审查现有五张地图，并在内存中比较算法；实际工作区仍为 revision 444，没有重生成或写回用户地图。

## 为什么之前大陆看起来大多是红色、黄色

这里同时存在显示问题和生成问题，不能只靠换配色掩盖。

旧气温色阶把 −25～35℃直接在蓝灰与棕红两种颜色间插值，约 10℃已经呈棕灰红色。这是配色造成的误读，不代表地图上所有地方都很热。只读统计中，五张现有地图的陆地年均温均值分别为 7.7、3.8、7.8、11.2、2.2℃，确实不能解释为普遍炎热。

旧降水色阶的黄色代表较干燥。本次检查发现，大范围地图原先的单向水汽输送会让水汽沿大陆一路耗尽；细网格中连续起伏又反复扣除水汽，容易把过大的面积推向干旱。现有 12000 km 世界图保存的陆地单元中，86.9% 的代表值低于 250 mm／年。因此黄色偏多既有真实缓存数值依据，也暴露出旧近似方法过干的问题。

这些缓存统计按保存的地理单元代表值计数，不能直接当作精确面积比例；地理单元的中心采样也不等同于细海拔网格平均值。

## 现在怎样读颜色

新色阶采用固定的物理阈值，区间之间连续插值。所有地图沿用同一组阈值，不会把每张图最干的地方强行画成沙漠、最湿的地方强行画成雨林。具体颜色与图例由同一份定义提供。

| 气温阈值（年均温） | 颜色含义 |
| ------------------ | -------- |
| −25℃               | 深冷蓝   |
| −10℃               | 浅冷蓝   |
| 0℃                 | 淡青灰   |
| 10℃                | 浅米色   |
| 20℃                | 暖金色   |
| 30℃                | 赭橙色   |
| 40℃及以上          | 暗红色   |

| 降水阈值（mm／年） | 颜色含义 |
| ------------------ | -------- |
| 0                  | 干燥土棕 |
| 250                | 沙黄色   |
| 500                | 浅黄绿   |
| 1000               | 草绿色   |
| 2000               | 青绿色   |
| 4000               | 深青蓝   |
| 6500及以上         | 深蓝     |

黄色降水区不必然是沙漠。相同降水量在寒冷地区与炎热地区的生态意义不同，生态分类还会考虑温度、海拔和蒸散需求。气温图显示年均温，不是夏季最高温或某一天的天气。

## 气温怎样计算

每个采样点先根据它在地图上的南北位置获得纬度，再计算：

```text
年均温 = 赤道海平面年均温
       − 0.52 × |纬度|
       − 0.0065 × max(海拔米数, 0)
       − 陆地内陆修正

陆地内陆修正 = 2 × clamp(距海公里数 / 1500, 0, 1)
```

默认的“赤道海平面年均温”是 30℃，不是整张地图的平均温度。例如北纬 38°的海平面基准约为 10.2℃；海拔 1000 m 再降低约 6.5℃。海底负高程不会使海面变热。

这是可调的年均温近似。6.5℃／km 是本工具使用的环境递减近似，并非把干、湿绝热递减率当作同一个常数。纬度的线性降温和内陆最多降低 2℃也只是创作参数，不能据此预测现实城市的年均温、夏冬温差或极端天气。

## 降水怎样计算，本轮改了什么

基本思路是让海面补充水汽，空气沿风向输送水汽，在抬升、经过陆地和远离水汽源时发生变化。赤道附近上升气流较强，副热带较干，中纬度风暴带较湿，是采用纬度权重的依据；现实中这些环流比本工具复杂得多。[NOAA：全球大气环流](https://www.noaa.gov/jetstream/global/global-atmospheric-circulations)、[NOAA：副热带马纬度](https://oceanservice.noaa.gov/facts/horse-latitudes.html)。

具体计算分为这些环节：

1. **纬度雨带与水汽容量。** 赤道与约 55°附近有较高降水权重，约 30°附近较低；较暖的海面能够提供更多水汽。它们都采用连续函数，避免纬度分段产生硬边。
2. **两个相反方向的输送。** 过去只有一个固定主风向；现在沿设定风向和反方向分别计算，再按纬度加权合并。中纬度优先设定风向，低纬与极地优先反方向，过渡平滑。另一方向仍保留一定权重，避免整片大陆永远只有一侧能获得海洋水汽。风向参数会同时旋转这两个方向，这是虚构世界的控制，不是完整的三维风场。
3. **按实际公里数耗散。** 水汽输送按地图距离计算，而不是简单“每走一格减少固定比例”。大陆横跨 12000 km 和城镇横跨 7 km 不会获得同样的内陆干燥程度。上风向数据使用双线性取样，斜向风也不会退化成整格跳跃。
4. **山地抬升与雨影。** 上坡增强降水，下坡造成一定减弱，水汽也会在越山时损耗。大气使用约 20 km 半径平滑后的地形，网格较粗时至少覆盖相邻一格；不让每个细碎山峰都制造一遍极端雨影。海底深度不计入大气坡度。
5. **有限水汽回收。** 陆地上把该步损耗水汽的 22%留在输送近似中，用来粗略体现水汽再循环；它不会凭空增加超过该步来流的水汽，也不是“实际降雨的 22%必然蒸发”的物理结论。蒸发、植物蒸腾及大气输送确实属于水循环，但这里的比例是创作模型的经验系数。[NOAA：水循环](https://www.noaa.gov/education/resource-collections/freshwater/water-cycle)。
6. **局部变化与范围保护。** 种子只提供约 ±7%的低幅局部扰动；总降水倍率再统一作用于结果。最后将年降水限制在 10～6500 mm。截取地图的边界允许区域空气携带水汽进入，不把图框外侧默认认作大海或永久沙漠。

双向输送是对年均情况下多种天气输送的简化混合，没有逐季模拟季风，也没有完整计算南北风分量、气压、科氏力、洋流和能量平衡。约 20 km 平滑、22%回收以及雨影强度都仍是可检验、可继续调整的经验设定。

## 同一份现有地形，审查结果怎样

本轮使用五张地图保存的细海拔数据，仅在内存重算旧算法与新算法的气候。种子、经纬范围、地图公里数与海拔相同，没有重画陆地或重新随机生成地图。以下是细网格陆地采样均值与低于 250 mm／年的采样比例：

| 地图           | 旧模型均值 → 新模型均值（mm／年） | 低于 250 mm／年的比例：旧 → 新 |
| -------------- | --------------------------------- | ------------------------------ |
| 城镇，7 km     | 1058.5 → 679.0                    | 24.1% → 0%                     |
| 区域，240 km   | 310.3 → 753.4                     | 69.8% → 0%                     |
| 城镇，4 km     | 1009.6 → 662.3                    | 29.5% → 0%                     |
| 世界，1800 km  | 252.7 → 769.4                     | 71.5% → 0.6%                   |
| 世界，12000 km | 85.4 → 294.8                      | 92.2% → 56.3%                  |

新方法并非统一把降水调高：两张城镇图消除了细地形造成的局部暴雨尖峰，均值反而下降。大地图获得了更多从另一侧进入的水汽，但 12000 km 世界图仍有大片干燥内陆，没有为了好看强行染绿。该图的高地与大陆跨度也会继续影响结果。

这组比较证明本次修正在同一地形上的行为差异，不能证明生成世界已经具有现实地球的降水分布。它不是与气象站或再分析数据校准后的气候模型。保存缓存与内存重算的网格采样方式不同，所以表中的旧算法均值 85.4 mm 不等于该图旧缓存代表值均值 143.4 mm，两者不能混用。

开发核对资料保存在本地 `.runtime/detail-climate-audit.json`、`.runtime/climate-audit.log` 和 `.runtime/climate-recompute-audit.log`；这里只列聚合统计，没有公开地图正文、账户或连接信息。

## 气候怎样影响实际地形与生态

气候不是独立的装饰图层。生成阶段使用同一份最终海拔计算温度、降水与水汽，再用于植被分类、土壤湿润程度和河流有效径流。生态先区分水体、冰雪、苔原和高山，再根据温度、海拔与“降水／蒸散需求”的比值决定荒漠、疏林、草地、森林等类型。

为了保留创作意图，用户明确画出的非草地覆盖具有优先权。例如手绘森林不会因为一次降水分类就被自动抹去；但过冷的森林会转成针叶林或苔原，低温热带雨林会转成温带森林。因此手工覆盖与纯自然分类可以存在差别，不能把每片手绘森林都当作模型独立推导出的植被。

目前生态规则仍是年均阈值分类，没有土壤、季节性降水、地下水与生态演替模拟；它适合为世界创作提供一致的自然约束，不能当作精确的柯本气候分类或真实植被预测。

## 为什么刷新旧地图后颜色或气候没有全部改变

已有地图保留已保存的生成快照。打开地图不会自动重算气候，也不会为了换算法重建大陆、河流、聚落或疆界。

程序更新后，新的显示色阶可用于旧快照中的原数值；新的降水算法则需要用户明确重新生成相关地图后才生效。不要把“显示颜色变化”误认成“底层气候已重新计算”，也不要为了看新效果在没有备份或确认的情况下重建正在创作的地图。

## 星球预览、经纬范围与距离的限制

星球环境预览复用生成阶段的气候函数，但仅使用 64 列粗采样，行数随长宽比调整。已有地图从保存海拔取样；新地图则根据种子、地图类型与尺度估算潜在地形。色块、海拔编辑和最终细网格会改变局部结果，所以预览适合判断大致冷暖、干湿及生态倾向，不保证每一片树林或每一条河的最终位置与数值一致。

星球上选择的经纬范围决定地图所处纬度及经度相关的微小变化；地图公里范围则决定水汽输送、距海效应等距离尺度。现在两者独立设置，程序不会强制它们符合地球球面上的同一段实际距离。例如把 7 km 城镇图设置为跨越半个星球，会在很小的公里距离里压缩很大的纬度温差，结果不符合通常的地域常识。城镇应选择窄小的地理范围，跨大陆世界图应选更大的范围，并让公里尺度与设想相符。

当前星球是方位与范围选择器，不是真实地球地形资料源；经度没有被用于模拟具体洋流或真实大陆位置。上述限制应在判断“这张图是否合理”时一并考虑。

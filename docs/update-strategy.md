# 更新、完整备份与恢复

日期：2026-10-13；程序：0.2.0-beta.6。本轮已实现完整私有备份、恢复工具和受签名离线更新。Windows独立环境已完成升级与失败恢复演练；Linux和Docker仍需实机验收。本文将当前操作与正式版剩余工作分开说明，实测结果以[开发日志](development-log.md)为准。

## 1. 用户只需做什么

beta.6更名后的包为.ccupdate，原beta.5更新入口也能读取，原签名密钥和数据格式不变。旧.wlupdate/.wlbackup继续支持。beta.4及更早程序仍需下文所述手动过渡；不能把旧无更新器的程序当作支持自动升级。

正常更新前保存编辑器草稿，并等到“所有更改已保存”。通过安装根的 `start.cmd`（Windows）或 `start.sh`（Linux）运行，主管理员在后台完成两步：

1. 点击“选择更新包”，选择发布者提供的 `.ccupdate` 文件。
2. 校验通过后点击“备份并更新至 …”。

程序自动准备运行组件、暂停写入、创建完整备份、验证恢复、切换版本和核对全部资料。成功后使用原账号登录，并在保留编辑内容后刷新页面。程序不自动刷新正在编辑的页面。失败会显示真实状态；恢复未完成时保留现场并要求修复，不能伪装成功或引导重新初始化。

普通用户和次级管理员不能更新、下载完整私有备份或恢复安装。后台的“创作 JSON”只用于创作内容交换；“创建并验证完整备份”才包含账号、权限和图片。

当前采用离线更新包，**尚无联网检查、下载发布源、定时备份或自动安装**。首次准备依赖和更新时的依赖准备仍需要 npm 网络或预先配置好的私有依赖源；“离线更新包”不等于完全断网可安装。正式版可补齐包含全部运行依赖的包及在线发布源。

## 2. 数据保护范围与兼容边界

| 项目         | beta.5实际行为                                                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 固定数据路径 | 启动器第一次将实际绝对 DATA_DIR 写入安装根 `.worldloom/current.json`，以后换程序不换此路径。新程序位于 `.worldloom/releases/`。              |
| 完整备份     | 数据库、全部普通上传文件和作者索引、安装设置、账户及授权、创作快照、显式指定的私有 `.env` 和散列清单。历史备份、更新缓存、进程锁不递归打包。 |
| 一致性       | 同一个维护门禁覆盖创作、上传、账号、权限与设置；先排空已接受的写入，再取得快照。单实例进程锁阻止同一个 DATA_DIR 被另一个服务打开。           |
| 恢复验证     | SQLite完整性检查并读取工作区；MySQL恢复到测试自身创建的全新库，比较领域内容后只删除此验证库；图片、私有文件和revision逐项校验。              |
| 更新来源     | 清单使用固定公钥验证Ed25519签名，校验每个文件、平台、架构、起点与格式；不是仅比较SHA-256。拒绝越界路径、链接、重复路径和超容量压缩包。       |
| 失败恢复     | 新版开放写入前失败时，恢复到全新目录/全新项目库，再启动原程序；原目录、原项目库、备份和失败现场保留。                                        |
| 新版已确认   | 完成记录在开放写入前持久化。一旦完成，即使开放保存请求的回应丢失，也不恢复升级前快照；正常重启/重试开放保存即可。                            |
| 浏览器旧页面 | 带旧版本号或缺少版本号的浏览器写入被拒绝；保留草稿并提示刷新。API脚本无Origin时可不带此头，仍受登录和权限检查。                              |

本版更新包仅支持**同一系统和架构**，且数据格式必须全部一致：MySQL schema 5、SQLite user_version 1、创作格式1、安装格式1、用户目录格式1。跨格式迁移尚未开放自动更新；先拒绝执行，等待对应版本经过迁移演练后实现。程序版本与数据版本分别管理，不靠版本号相近推断兼容。

SQLite在执行DDL前读取user_version，MySQL在DDL前读取现有迁移版本；更高未知版本拒绝启动，不把版本号降回当前值。安装和用户私有格式也在打开业务数据库前校验。已有本地库但缺少安装配置时拒绝重新安装。旧beta程序没有这些完整门禁，不能拿旧程序直接打开不兼容的新数据。

SQLite备份使用Node内置在线backup API，包含已提交WAL内容，再将**副本**整理为独立文件；不直接复制运行中的主库文件。[Node 22.18 SQLite backup](https://nodejs.org/download/release/v22.18.0/docs/api/sqlite.html#sqlitebackupsource-db-path-options)。仍为单Node进程服务，不支持另一个程序同时直接改库或上传目录；外部直接写入不在应用维护门禁内。

MySQL完整备份限定本项目标准schema 5和InnoDB表，保留行数据、建表结构、utf8mb4字符集及实际排序规则；额外表、视图、触发器、例程、事件及结构不一致会拒绝更新。验证/自动恢复要求账号有创建新项目库和删除其自身验证库的权限。只有本轮新建的验证库会删除；原库与失败的恢复库不删除。恢复始终先确认新库名不存在，再执行 `CREATE DATABASE`（没有 `IF NOT EXISTS`）。当前连接格式未单独验收含特殊TLS参数的MySQL部署。

## 3. 完整备份与迁机

主管理员点击“创建并验证完整备份”，成功后列表标为已验证。备份保存在实际数据目录 `backups/full-…`。需要带走时点“下载私有备份”，再次输入当前主管理员密码；下载的 `.ccbackup` 包包含账号密码哈希和数据库私有连接配置。

私有备份**目前不加密**，必须存放在私人或加密磁盘，不能发到公开仓库、公开网盘或静态网站。重认证是因为包包含整套安装凭据。程序不自动清理历史完整备份；请检查磁盘空间。保存在同一硬盘不等于异机备份，可定期下载到另一台机器/私有存储。

迁机使用与备份格式匹配的程序，在服务停止状态执行：

```sh
node --import tsx scripts/recover.ts /private/full-backup.ccbackup /private/new-chronicle-cartarium-data
```

MySQL增加一个**尚不存在**的项目库名：

```sh
node --import tsx scripts/recover.ts /private/full-backup.ccbackup /private/new-chronicle-cartarium-data chronicle_cartarium_recovery_new
```

Windows可把命令里的 `node` 换成安装根 `runtime\node.exe`，路径有空格需引号。目标目录必须全新，已有目标一律拒绝。MySQL私有连接中的服务器必须可访问并有建库权限；迁到另一数据库服务器的配置接入仍需维护者处理，不是网页自动换库。程序不会修改已有原库。

确认恢复成功后采用新目录：直接Node服务设置绝对 `DATA_DIR`；使用启动器的实例先停止服务，再改安装根 `.worldloom/current.json` 的 `dataDir`。该指针优先于环境变量，避免更新后意外回到另一个空目录。检查登录、世界/地图、图片、权限与revision，再允许创作。恢复包里的 `environment.env` 只供维护者私密采用，不自动替换服务器环境。不要删除尚未确认的原数据或失败现场。

## 4. Windows与Linux，本机与服务器

Windows便携安装使用固定安装根的 `start.cmd`，数据仍在安装目录，程序版本另外存放。普通更新不用手动搬文件或换数据库。固定安装根不能只复制一个新版releases子目录当作整套安装。

Linux本机使用 `sh start.sh`；系统需提供Node 22.18+与npm。共享启动器用Node实现，不依赖盘符。当前Windows包自带的node.exe不能用于Linux；Linux发行与不同架构包仍需各自构建和签名。本轮没有Linux实机升级/恢复结果。

长期服务器的systemd或Windows服务管理器监督固定入口 **`node scripts/launch.mjs`**，工作目录固定为安装根，保留原环境及HTTPS配置。网页只提交受约束更新任务，启动器负责自己的子进程；不能结束其他Node进程，也不执行网页传入的任意命令。直接 `npm start` / `node --import tsx server/index.ts` 属于手动管理，后台会提示使用启动器，完整备份仍可用。

当前启动器继续使用安装根Node运行时启动新版服务，更新包不自动升级此固定运行时；Node大版本升级需单独维护和验收。服务账户需能写安装根`.worldloom`和实际数据目录；只读程序目录应先设计外部可写发布目录，不能假称已支持。

### 从beta.4及更早版本接入beta.5

这是一次手动过渡：所有人保存，停止旧服务，记录**实际**DATA_DIR绝对路径并完整停机备份；将beta.5解压到独立安装根，明确DATA_DIR为原路径并保留私有配置，用新根启动器运行。保留旧程序和数据。若出现安装向导应立刻停下核对路径，不能重新填例。后续beta.5起才可使用受签名更新入口；此beta.5包不能被旧beta.4网页直接导入更新。

没有升级schema，本版保留MySQL 001～005和SQLite1。适配旧安装时不重填范例、不重置账号或更改创作revision。旧程序与数据库之间的兼容要按发行说明确认，不能据此承诺所有未来版本均可直接降级。

## 5. Docker宿主机更新（待实机验收）

容器后台显示宿主机操作指引，不挂Docker socket。宿主机安装Node并在原Compose目录运行一次：

```sh
node scripts/update-docker.mjs trusted-registry/chronicle-cartarium@sha256:完整的64位摘要
```

只有原项目不能由当前目录识别时，前面增加原Compose项目名。必须选择维护者认可的镜像来源和完整摘要；尚无公开镜像仓库，本项目没有将镜像发布到外部。镜像标签检查MySQL5/SQLite1，摘要固定内容；**目前没有OCI发布者签名验证**，不能把摘要当身份认证。

入口查明当前唯一app容器及原持久挂载，先拉取镜像再维护，自动完整备份并复制到宿主机 `.worldloom/host-backups` 校验，再仅替换app。核对实际挂载身份和领域/账号/图片，完成后开放写入。正常Compose更新会重建变化的容器并保留已挂载卷，[官方up说明](https://docs.docker.com/reference/cli/docker/compose/up/)。本入口额外检查实际卷；不能在换目录后默认创建一个空卷。

后续Compose操作继续使用原项目名、原配置以及 `.worldloom/docker-update.json` 覆盖文件。失败时旧镜像从宿主机备份恢复到原卷内新目录/全新项目库，修改DATA_DIR后启动，原数据保留。**不要执行 `down -v`**；它会删除由Compose管理的相关卷，[官方down说明](https://docs.docker.com/reference/cli/docker/compose/down/)。卷配置的身份约束参考[Compose volumes](https://docs.docker.com/reference/compose-file/volumes/)。外部MySQL也在完整备份中，不能仅备份应用卷。

当前Docker流程是待验收实现，主机命令被强行中断后可能保持维护，需要维护者检查状态并完成更新或显式恢复，尚无完整的主机中断续作入口。容器PID命名空间与陈旧实例锁也需实机演练。没有Docker/WSL Linux运行环境的本轮不能把源码检查当成实际成功结果。

## 6. 发布者与后续开发

发布包白名单不含真实data、`.env`、`mysql.txt`、私有账号、运行控制密钥或开发node_modules。使用 `npm run package:beta` 准备目录，发布者私有签名密钥已配置，运行：

```sh
node --import tsx scripts/sign-release.ts .runtime/release/实际发布目录
```

签名私钥仅存 `.runtime/release-signing-private.pem` 或指定的私有位置；必须另做私密备份，换电脑继续沿用，不能提交/公开或装进用户包。公钥在 `shared/release-trust.ts`。`scripts/release-keygen.mjs`只用于首次建立信任；已有公钥但丢失私钥会拒绝重建，不能让旧用户失去验证未来包的能力。密钥轮换需单独设计。

先完成程序、文档和构建，再签名；签名后改任何发行文件必须重新签名。release manifest同时校验package、服务端版本与前端app-version，避免程序更新而网页仍是旧版。当前压缩包上传128MiB，解压更新512MiB，恢复包最大10GiB/10万文件；很大的实例需后续容量与流式下载验收。

正式版剩余门槛：Linux本机/systemd、Windows服务、Docker及两种数据库的更新矩阵；断电/主机中断/锁竞争演练；大图片和大库空间预检；跨schema迁移的试迁移及校验和；完全断网安装依赖包；在线发布源、签名镜像、定期加密异机备份、便捷恢复界面。当前不默认无人值守安装，不把未验证平台称为正式版可用。

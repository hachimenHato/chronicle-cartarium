# 架构与数据约定

## 在线来源与受保护的程序更新（2026-10-26）

shared/update定义在线来源、频道、发行候选和下载任务，与监督程序的持久安装阶段分开。beta.20 界面新增 china 选项，对应内置“国内下载源（腾讯云）”固定根地址 https://files.hachimen.info/chronicle-cartarium/updates；github 默认与 mirror 自建接入口保留。china 只作为写入输入别名，服务端统一规范化为 source=mirror 与固定 mirrorBaseUrl 后持久化及返回 API；因此原 beta.19 固定桌面 worker 仍可读取，无需先更新壳。shared/update-sources.json 是公开名称与地址的唯一来源，updateSourceChoice 从规范设置识别预置选项，前端保留独立三值草稿，任务来源在开始下载时快照，回退 GitHub 时更新实际标签。server/online-update管理主管理员的来源配置、缓存检查、下载进度与取消；GET状态只读取本地进度，显式检查才访问公开发行列表。只选择严格版本标签及当前系统/架构的标准`.ccupdate`附件，镜像元数据仍指向固定官方仓库；镜像实际包为BASE/vVERSION/FILENAME，清单为BASE/releases.json。失败回退GitHub，不接受任意元数据下载地址或未知公钥。Windows桌面壳同样解析该来源偏好，不接收COS凭据。

server/update-download负责逐跳HTTPS、公开DNS结果验证与绑定、重定向/时间/流字节预算、流式写入新文件、精确大小与SHA-256检查；不发送登录Cookie、应用令牌或数据库配置。准备阶段再由release-package使用原固定公钥验证签名、文件、版本、平台及数据格式。ProgramUpdateService对在线下载/验签、离线导入和提交安装串行互斥；网络下载不持有创作维护门禁。只有已准备并再次校验的包才能写pending-update，后续仍由固定scripts/launch.mjs完成备份和切换。

ProgramUpdatePanel只对本次点击产生且仍匹配的下载任务保留自动安装意图，完成后重新检查当前canUpdate、可见性和组件生命周期；有草稿或离开页面时只保留已验证包。重新进入不会自动应用旧任务，不自动刷新；提交apply仍由服务端重新验证主管理员权限和包身份。源配置仅为安装根.worldloom中的非创作偏好，不改变workspace、revision或业务数据库；该偏好不在创作JSON/完整资料恢复的保证范围，换机可重新填写。

scripts/create-update-mirror.mjs从本地公开清单与平铺的原始包生成全新静态镜像，过滤非更新附件/多余字段、拒绝重复或不匹配包，复制后复验并最后写清单；不含签名私钥，也不联网发布。scripts/publish-cos-mirror.ts 只同步五平台官方签名更新包与Windows桌面ZIP、签名描述，普通完整安装TAR/CMD ZIP不在白名单。版本对象禁止覆盖，逐包匿名全文SHA校验后才提交净化清单；发布队列中的版本尚不算国内可用。维护SDK隔离在tools/cos-publisher，凭据只注入工作流最终上传步骤，应用和镜像中均不包含它。Docker不在Web进程控制宿主机，Electron壳和固定Node运行时不由后端更新替换。当前实现和验证边界见[更新说明](update-strategy.md)及开发日志。

## 可丢弃的完整底图显示缓存（2026-10-21本地补丁）

Atlas将地形与纸面集中在data-map-cache-source组，useMapRasterCache只在源图改变时准备独立HTML Canvas；地名、军线、笔画、标记和编辑覆盖继续由SVG绘制。原底图仅通过外层CSS隐藏颜色，保留命中；导出仍克隆原SVG，缓存不进入领域模型与存储。源图变化立即恢复原矢量，异步字体／上传图片／解码受版本号约束；手势中不替换显示，切图或卸载释放资源。

map-raster-cache纯函数规划完整绘制边界、最高400%与DPR像素、xMidYMid meet矩阵。Canvas与SVG共用相机surface，避免把临时getScreenCTM再套一次。边界包含几何、描边和模糊外扩；超过4000万像素／单边16384或无法解码时回退原SVG，不降低生成精度。窗口、DPR、全屏和字体变化失效。准备耗时、内存限制、纹理采样差异及实测见[地图性能说明](map-performance.md)。

## 连续缩放相机（beta.16）

useMapPanCamera统一维护已渲染base、最新next及未确认commits。平移／缩放只改变同一HTML surface的translate3d／scale；停止400ms或落笔前finish才更新原SVG viewport。layout阶段确认提交后重base，若已有后续输入则重新计算剩余CSS矩阵，不清掉新手势。replace统一处理重置、定位和地图切换等程序视图，取消旧RAF／idle；尺寸和全屏变化结束当前手势。

map-camera中的纯函数按M·Vnext·Vbase⁻¹·M⁻¹得到CSS变换；M包含viewBox留白与屏幕到本地CSS比例。落笔前同步呈现最后CSS，getScreenCTM读取真实显示坐标；数据仍以地图坐标保存。百分比独立span ref只在文本改变时更新，不驱动Atlas每帧重渲染；CSS使用原始字符串缓存，不比较浏览器规范化后的style字符串。平移首sample同步呈现，后续采样按RAF合并，不变变换不重复写。

Atlas普通pan直接进入相机，不为闲置编辑工具反复读矩阵；区域选格拖动仅在相机不可用时计算备用坐标。SVG导出仍移除屏幕视图，临时HTML相机不进入档案或导出；生成、缓存签名、权限与revision协议均不变。性能检查只用3311合成图，完整对象与纹理不删减。滚轮合成事件会将小数光标量化，测试应反投影实际event.clientX/Y，而不是拿请求的未量化坐标当锚点。

## 图例边距与地图入口（beta.15）

AtlasLayout以同一组header／footer／rail／edge变量预留控件空间，stage保持显式高度并作为size container。图例摘要与画布左边缘对齐，展开宽高按绘图内容区cqw／cqh约束，包含边框与内距；向上展开时另留底栏间隔。容器单位已排除stage内距，不能再次扣除，避免手机图例过窄或过矮。工具轨保持独立滚动，纯地图全屏隐藏全部常驻控件。

Atlas选中pin仅显示详情，不隐藏writable用户的五个工具页签；切页签清理selectedPinId，浏览操作不提交工作区。MapStudioPanel明确random来源及其与sketch ABC控件的区别。新安装范例仍由shared/example提供配方，不向已安装工作区注入重生成或初始化；范围与安全使用见[范例地图说明](example-maps.md)。无持久契约或数据库schema变化。

useComposedTerrain接受生成结果时，将派生海拔显示场从同一整米快照恢复，再用于等高线／地势显示；原模拟objects和geography保留。避免首次浮点显示与保存／重做／重开后的整米显示产生细小轮廓差异。存储原本就以整米为单位，此处没有降低已有保存精度或修改实际地图。相关UI对完整几何记录计算SHA-256作严格比较，避免失败时对多MB路径字符串生成无界差异报告。

generationSignature对物理输入的JSON对象递归按键排序，保留数组顺序与undefined的JSON语义，避免服务端校验重排字段后使有效快照失效。legacyGenerationSignature保留原散列，matchesGenerationSignature同时检查新签名与当前原始配方的旧签名；hook恢复旧快照时仅把内存结果标成当前签名，不创建待保存snapshot、不发Worker、不写回旧档案。真实五图在改动前均匹配旧签名，改动后均能通过双签名只读检查；这不是任意接受无效旧缓存。

Atlas显式把海拔草稿状态经EditorArtwork.elevationPreview传给合成层，与regionPreview共同控制snapshot提交。预览提前完成时不接受保存；松手后preview由true变false，使同一已完成snapshot再次进入提交effect。仅依靠父级拒绝草稿不足以保证松手后再次提交；本轮保留父级守卫与预览期间零写入校验。

## 连续地貌与群落填充（beta.14）

terrain-motifs是13类×8结构的原创细纹库；terrain-texture使用全图稳定错列采样和连续群落，不再缩到每个地理cell内部。单次索引地理单元和可见障碍，细海拔拒水，最终沿真实海陆clip；旋转文字／聚落／河路周围留白。均匀置换采样顺序把几何预算分散全图，避免预算耗尽时最后一排突然变空。按类合并最多41条path；固定mark、采样、索引和字符预算，输入不变、确定性输出。

terrain-relief从同一保存细海拔计算宽／细坡向、环境明暗及六组生态洗染，以共享平滑等值轮廓合并最多37条path，光影和存在的生态类分别分配预算。TerrainRelief与TerrainTexture均memo，绘于GeographicArtwork的underlay，实际地图对象在其上。无额外滤镜／位图／逐草DOM，不改变持久结构、签名或生成随机序列。具体参考、显示层次、预算和限制见[地貌美术说明](terrain-art-direction.md)。

## 地貌、气候与合成平移（beta.13）

TerrainTexture按地理单元及保存细海拔建立原创雕刻纹理，按13种陆地biome合并墨／影／亮path，并缓存结果；海湖采样排除且沿真实陆地clip，underlay位于河路建筑文字下。administrative-borders从省／地区／街区areas.cells与共享cell边建立归属，分弱网格／中等行政边／强国界，跨国家边不重复充当省界。新纹理和边界为派生显示，不增大持久快照或消耗生成随机序列。

useMapPanCamera以受裁切的HTML frame包含原SVG surface，拖动只对外层进行动画帧CSS平移，不改内部SVG坐标或替换位图；松手更新一次view并在layout effect清临时变换，维持同一屏幕位置。useFrameState第三项latest返回待提交值，确保两个手势在同一帧内仍累计；尺寸／全屏改变结束手势，切图清理，疆域拖动共用相机。SVG导出继续清除内层视图transform并保留完整矢量内容。

geography-climate现在将两个方向按纬度风带加权，约20km宽的有效地形平滑减少微小高程反复耗水，陆地至多22%的本步水汽损失视为回补；保留真实公里尺度、海温容量和迎风雨影。温度公式未改。thematic-colors提供固定七节点数值色阶，地图／预览／图例共源，ClimateLayerGuide只统计已保存地理单元。旧快照不自动失效，模型／存储schema不变；详见[气候模型说明](climate-model.md)。

globe-navigation按投影后实际选区计算聚焦倍率，最高16384倍；GlobeExtentPicker支持滚轮、几何步进、小步旋转、局部经纬网和定位小球。高倍率投影提高精度及小数位并裁到视窗；选区使用不做矩形裁切的投影，避免把视窗边框画成选区边界。只改视图，不修改选区尺寸或真实生成参数。

## 港口、地图显示与星球环境（beta.11）

## 专题底色、气候与星球范围（beta.10）

thematic-colors定义地形专题的独立土色／植被色及蓝色水域，地图图例共用，源色块调色板不变。GeographicArtwork在underlay中对地形／气温／降水单组使用小范围SVG Gaussian blur，海岸／湖岸在滤镜外裁切；细节和名称不受滤镜影响。滤镜defs保留在自包含SVG内。兵棋翻转只反转原points，不新增军事字段；前线验证仍沿相同共享边，GeographyPanel按行提供操作。

geography-climate从地势生成中独立，年均纬度／6.5℃每公里海拔近似、按温度的水汽容量、雨带、双线性迎风取样、公里尺度输送消耗、迎风抬升和背风雨影共同决定气候。湿度步进按真实grid dx/dy和coverageKm计算，避免整数格风向和分辨率依赖；水下地形在大气坡度计算中视作0，不再重置每个海面格的相同雨量。geography-fields随后把结果传回biome、径流和地理单元。公式系数为创作近似，不是气象预测或季节／洋流模型。

shared/world-extent管理南北纬和可跨日期变更线的东西经端点。GeographicSettings的longitudeWest/East成对可选，老配方不回填；新三类型缺省global。server/geographic-validation检查范围／成对／零宽，MySQL editor_data与SQLite JSON直接保存，无DDL。GlobeExtentPicker是原创SVG球面正投影＋阴影，原生交互旋转与选区，不引入外部三维依赖；createPortal独立弹窗处理键盘和焦点，取消不改创建表单。星球位置只是一组方位／范围，示意陆地不进入生成器。范围进入generationSignature；纬度参与温度／雨带，经度参与一致的低幅气候变化；MD／JSON／真实MySQL同步。

## 地图视图、地名与色块三档（beta.9）

shared/map-layers为十图层唯一名称契约，MapLayerBar只持有视图选择，不改生成配方。Atlas的工具、疆域类型、右面板与图层状态互相独立。MapArtwork通过GeographicUnderlayRenderer注入显示底层，把生成结果分ground／underlay／detail，最后overlay边、港、标签；不直接导入带tooltip样式的GeographicArtwork，保持纯SVG组件可在Node独立导出。恢复持久缓存要读取generated.geography，不能假设恢复分支有snapshot属性。map-artwork-layers只归类底色地表，不能把山峰、树冠或河岸多边形误作ground。political着色因此不染细节文字。

cartographic-labels在地图坐标内计算主轴轻弧与碰撞盒，考虑真实聚落组件占地、陆地／水面、同区域和其他名称；标签派生而不存布局。障碍数组memo，使平移不重算。有关联的曲线字使用SVG bounding-box命中，让字间空白也能触发摘要和导航，未关联字不拦截画布。MilitaryArtwork消费military-artwork纯几何，前线保原共享线，进攻／撤退／防御采用不同方向符号；所有SVG路径与defs随画面导出。

## 地理地图生成（beta.8）

水域权威为持久细海拔：shared/map-surface精确检查连续双线性网格线段；water-routing在细网格寻路、分量预筛与受水域约束的圆角采样，geography-navigation定位真实港湾。服务端复用同一检查拒绝越陆与港湾端点错连。粗政治单元的land可含岸边水域，不能当作海路导航图。MapSurfaceDefs按实际海岸／湖泊环提供陆地裁切与水域遮罩；GeographicArtwork画连续轻国界与细海路。

geography-mesh在政治扩张时读取聚落、真实河道、山脊、坡度和海峡，三类分区采用不同阻力；geographic-borders把持久共享边拼链、截湖并补接海岸，仅影响表现、不修改共享拓扑。geographic-associations复用正确世界／类型的词条并按权限建立不足草稿，Atlas的onCommitGenerated经App一次状态提交把新条目与地图一起保存。领域结构不变，无SQL DDL；权限与revision事务仍由服务器控制。

geographic-selection及useGeographicSelection持有仅前端的单元选择，单击／Shift路径／Ctrl相连归属组不保存；GeographyPanel明确填充／清除后才更新归属及共享政治边。拖动平移、点击细水面不选区。疆域分区入口使用该流程，不开放旧自由画笔；快速新建分区与词条也原子保存。GeographicSelectionArtwork标记data-editor-overlay，SVG导出移除选区。

shared/geography定义专业地理近似契约，shared/generated-map定义生成快照和军线，挂到cartography编辑数据。生成、绘图、用户编辑分离；geography-fields负责板块与高度、纬度／海拔温度及风向输送降水，sketch-generation-v2用这些值重新构造地貌／径流与原柔和河路，geography-mesh通过d3-delaunay建立共享不规则邻接区域及政治层／地名，geography-navigation优先选沿海聚落并在水域寻路。三个地图类型使用不同单元密度，细地势采样与政治单元粒度独立。

useComposedTerrain先核对持久化生成源摘要，已有合法快照不开生成任务；只在源变化或显式失效时派发Worker。海拔视图从已保存高度绘图，改名／锁定／图层不影响摘要。MapArtwork只把非笔刷草稿的最新结果回传；Atlas再次与mapsRef当前源核对，在原修订事务保存，不会把失败显示为成功。军线／地名／单元归属都是独立持久编辑，历史栈共享不可变大快照以避免40次完整复制。前线依共享陆地边图寻路，服务端再校验点和线段的边界约束。

server/geographic-validation限制字段、预算、数值、坐标与内部关系，完整档案15MiB；server/permissions按已关联词条过滤私密地名、政治归属与缓存文字，公开写入合并隐藏部分。MySQL editor_data JSON与SQLite地图document JSON直接携带新契约，无新增DDL，revision事务不改。src/lib/export输出地理摘要和军线，原JSON保存完整快照与图层。细节、依据及已知模型范围见[地理生成说明](geographic-generation.md)。用户允许重建旧地图仅适用于地图数据，不能清空其他创作资料、账号或数据库。

connectionLanes按边ID稳定排序，为共用节点边界分配有限偏移，并为平行/反向边分配轨道。ClueEdge在Dagre有效路线和手动布局回退路线中应用偏移，反向连接绕过卡片上方；关系图适度增加初始视野留白以容纳标签。偏移为派生显示，不新增持久化字段；松手保存节点坐标与现有权限/revision约定不变，不保证任意密集网络平面化。

人物关系与剧情各自使用ClueLabelProvider协调注释：ClueEdge采样浏览器实际SVG路线，测量标签与节点尺寸，按动画帧合批交给clue-label-layout。后者以空间索引查询所有路线（含无标签路线）、节点、已放置注释和交叉处，在路线旁选择注释位置，以细虚线与锚点关联；无干净位置时退为透明背景以减少遮挡，不能保证极端密集图完全无重叠。悬停路线、悬停或键盘聚焦注释时突出该连接并淡化其他连接；注释按钮沿用已有编辑入口和权限。注释布局与高亮是派生状态，不写回节点坐标或触发保存，节点仍仅松手后保存，视野不因注释测量重置。

## 0.2.0-beta.2：创作结构与权限

shared/access定义身份、模块创建/修改/删除范围与单条覆盖。主管理员管理世界档案和系统；次级管理员管理全部创作、类型/字段模板、档案导出与用户；普通用户默认只读公开内容。创建记录由服务端赋createdBy，旧未赋作者的记录归主管理员，既有作者不可在普通快照写入中伪造或改变。

server/permissions同一投影用于读取和写入比较：私密记录、不可见关系端点、地图关联区域/标记过滤，剧情引用的变量须可读。写入逐条核对模块/作者/单条允许禁止，保留隐藏记录和隐藏地图部分；InstallationManager在队列内读取当前revision与最新账户，再进入存储事务。名称引用维护由服务端机械同步；删除被无权修改的内容引用的条目或变量拒绝。上传文件归属索引在uploads/.owners.json，资源读取、引用与正式导出/完整备份/系统接口独立检查。

World.entityTypes为可选完整类型目录，缺省13内置类别，角色类别保留，custom_稳定ID最多30字符，删除使用中的类型拒绝。entityTemplates接受对应目录键；非角色Entity.cover为上传引用，graphPosition保存人物线索位置，Plot.layoutVersion=1标记显式保存的场景布局。MySQL迁移005新增world.entity_types、实体cover/graph_position、六类创作created_by、非实体visibility及plot.layout_version，逐列检查支持中断DDL恢复；SQLite聚合JSON直接往返。所有新增列可空，不回填旧创作或增加workspace revision。

关系与剧情使用[Dagre官方布局接口](https://github.com/dagrejs/dagre/wiki)（3.1.1）分层、留间距、处理循环与无连线卡片；线段用圆角路由，手工位置改变后可回退为动态弯线。ReactFlow通过onNodesChange维护本地拖动，仅松手保存。useWorkspace确认服务端数据时用reconcileSnapshot保留未变化几何引用，接受作者归属和服务端关联修正，同时避免旧响应覆盖新草稿。

v2配方settlementCounts按五类保存上限，单类24、合计60；settlementNames按类型/序号保存，默认名称与计划在settlements模块统一。名单为Worker派生结果，不自动创建知识库实体。不同类型屋群、符号与尺寸有区别，周边建筑按世界/区域/城镇地图取较多/少量/零的目标，未实现真实城市街区规划。Worker缓存一个地理结果，名称编辑和显示海拔切换可复用；不可用Worker时保留完整回退计算。老配方未声明类型数量时保留原有生成绘制，新建自动地图直接使用五类组合。JSON保留完整配方，MD列出类型上限与手动名称，SVG保留实际画面。

创作指引与工具速查分开，ToolTour以实际元素矩形高亮、自动翻页到对应模块，空白工作台创建世界后继续完整教学；状态按账户存私有目录，侧栏可重播。主题CSS在基础样式后加载，地图工作面保持独立纸色。TOOLTIP_SHOW_MS=1000控制显示等待，TOOLTIP_LOCK_MS=2700控制显示后的锁定，与锁图标动画使用同一常量。未对大规模多用户、极端图规模、Linux、Docker或公网做完整验收。

## 1. 分层

```text
浏览器
  React 19 + TypeScript + Vite
  世界工作台 / Markdown / SVG 地图 / React Flow 图形
          │ HTTP JSON + 图片上传
Node.js / Express
  身份校验 → 输入校验 → 工作区服务 → 数据仓储
          │ 参数化 SQL、事务、revision
MySQL 8                         uploads 资源目录
  规范化实体与关系                  图片二进制
```

- `shared/`：前后端共用的领域模型、模板和纯逻辑。`model.ts` 是字段名的事实来源。
- `src/`：界面与交互；图形位置和内容均进入领域数据，不能只存在组件临时状态。
- `server/`：API、登录、校验、存储、迁移与上传；禁止把生产数据库密码发送到浏览器。
- `tests/`：具有业务意义的验证，例如引用一致性、条件引擎、导出范围与修订冲突。
- `docs/`：需求、研究、架构、日志和交接。

组件具体文件名与端点以现有源码为准；后续重构须同步本文。

当前 API：`GET /api/status`、`GET /api/workspace`、`PUT /api/workspace`（`{data,revision}`）、`POST /api/login`、`POST /api/logout`、`POST /api/uploads`。上传使用 multipart 字段 `file`，正文 JSON 上限 16 MB，单张图片上限 8 MB。工作区冲突使用 HTTP 409。

## 3. 规范化存储

用户要求新建独立数据库，现有数据库不动。部署与迁移必须在全新唯一库名下操作；`DATABASE_URL` 指向该新库，首次迁移前验证目标，禁止对已有业务库运行初始化或清理脚本。这是用户约束，不是可选运维建议。

世界、条目、地图、关系、剧情、会话、变量独立存表；地图标记/笔画、剧情节点/边作为独立子记录，字段集合和实际约束查阅数据库迁移文件。正文、动态属性与坐标点集合可以使用合适的 TEXT/JSON 列；整套工作区不能仅塞入单个 JSON 文档来冒充关系数据库。

初始 `server/schema.sql` 包含 11 张业务表：`world`、`entity`、`atlas_map`、`map_pin`、`map_stroke`、`relation`、`plot`、`plot_node`、`plot_edge`、`game_session`、`state_variable`；另有 `schema_migrations` 与 `workspace_state`。世界引用和主要结构关联有外键；变量在世界内有名称唯一约束。JSON 内的关联 ID 与同世界约束由服务端额外校验。

`server/migrations/002-map-editor.sql` 为项目专用库的 `atlas_map` 增加 `editor_data JSON NULL`，不增加业务表。NULL 对应未使用新编辑器的旧地图；仓储读取时不凭空加入 `editor`，写回时保存可选编辑文档。迁移执行器在 schema 锁内检查列是否存在及其类型，再记录数据库版本 2，允许 DDL 成功而版本记录未提交后的安全重试。**数据库迁移版本 2 与 `MapEditorData.version: 1` 是不同的版本号。** 不重置工作区、不修改其他数据库，也不借此回填或重新生成旧地图。

区域与矢量对象属于一张地图内部的有序绘制文档，采用受校验 JSON 保存可变几何、属性和排列顺序；地图、标记、旧笔画及跨领域关联仍使用原有规范化记录。服务端对新数据执行严格字段、枚举、有限数值、颜色格式、几何最少点数、对象数量和 ID 一致性检查。当前每图上限 200 个区域、8000 个独立对象，每个几何最多 2000 个点；同时受整个工作区 16 MB 请求限制。容量常量以 `shared/cartography.ts` 为准。

首版客户端以完整工作区快照读写，服务端把快照在一个事务中转换为规范化记录。这简化首版的一致性，代价是大世界写入放大、多人同时修改时容易冲突。下一阶段可按聚合提供细粒度 API，但不能提前承诺实时合并。

读取快照时，`store.ts` 按表取完整行，再在 Node 按数值 `sort_order` 排序，随后组装父子数组。不能恢复为 `SELECT * ... ORDER BY sort_order`：携带大型 `editor_data` JSON 的行可能触发 MySQL 排序内存不足，导致整个工作区无法读取。排序仅改变行引用顺序，不修改存储数据，事务隔离与 revision 逻辑不变，也不调整服务器全局参数。当前本来就全量读取，未来分页 API 应另行设计索引与排序。

写入流程：验证结构和大小 → 检查跨对象引用 → 开始事务并锁住修订记录 → 核对客户端 revision → 原子更新 → revision 增加 → 提交。冲突返回 409，客户端保留现有编辑并给出恢复办法。数据库错误不得导致生产服务切换到演示文件。

## 4. 地图、图形与悬浮阅读

地图采用内部统一坐标系，显示缩放不改变存储坐标。种子控制随机底图；笔画和标记叠加在生成层上。区域、城镇与世界地图通过父级和标记关联，避免把所有细节挤进同一张图。

三级编辑共享 `AtlasMap`，`mode` 只控制工具呈现：`sketch` 用四色语义笔刷快速生成；`sculpt` 提供 14 类地貌、区域参数与辅助群组，旧 v1 配方仅开放原 7 类；`detail` 提供直接的矢量对象与节点编辑。`src/lib/cartography.ts` 承担纯生成、几何和对象转换，`src/components/useMapStudio.ts` 处理编辑交互，`MapStudioPanel.tsx` 提供面板，`Atlas.tsx` 负责主画布整合；65 种图章由本项目矢量定义绘制，不依赖竞品素材服务。

区域保存种子和参数，绘制时产生稳定的轮廓及装饰；独立对象直接保存最终几何和样式。显式转换操作把随机底图、区域生成结果和旧笔画拆为独立对象，保留 `pins` 及其关联，隐藏原随机底图并移除已转换源内容以避免重叠。转换前检查总容量，超过上限拒绝整次操作。转换及普通编辑进入同一地图撤销/重做流程；撤销栈是会话内临时状态，结果由 revision 保存队列持久化。模式切换不会触发转换。

转换保留语义几何而非逐像素外观。旧底图的纹理、海岸光晕及虚线装饰没有完整的对象属性对应；曲线会采样为控制点，旧符号以当前原创矢量符号表达。验收时应分别检查内容与叠放顺序保持、对象可编辑性和外观差异，不能以“转换完成”声称无损还原。

`MapObject.layer` 缺省为 `detail`，保持早期独立对象位于区域之上的行为。画布顺序是随机底图 → `base` 对象 → 区域 → `detail` 对象 → 旧笔画 → 标记；每组内部按数组顺序绘制。转换也按此顺序收集内容，最终对象统一归入 `base`，以便后续区域仍可覆盖已转换的地形。不能把整个对象数组一律绘制在区域之后，否则转换产生的背景会遮住新绘制的色块。对象的上移/下移只在同一图层中调整，跨层修改通过显式属性完成。

SVG 导出包含当前可见地图内容并去除编辑辅助控件，适合独立查看；Markdown 导出保留地图元信息、编辑级别、区域和对象摘要、标记清单，不能重建全部矢量编辑状态。完整 JSON 备份保存 `editor` 文档，恢复经过同一服务端校验。

关系图使用条目作为顶点，关系作为有向连线；剧情图使用独立场景作为顶点。两种图的语义不同，不能共用同一组关系来简化实现。拖动布局如需持久化，必须有对应领域字段或明确恢复策略。

`EntityTooltipProvider` 以当前世界已授权条目集合统一处理失焦、外部点击与计时器，不要求Ctrl/Meta；`useEntityTooltip` 供正文链接、地图关联等入口复用，卡片通过 portal 绘制。`src/lib/entity-tooltip-state.ts` 的状态机记录父子卡片、锁定和定位。1000ms连续悬停或聚焦后显示，挂载定位后才开始2700ms锁定；提前移开取消待显示，未锁定卡片保留120ms移入桥接。子卡片按父引用建立，已锁定父卡片内的词条可继续展开并独立等待和锁定；祖先链中的同一条目不重复展开，避免循环引用无限堆叠。Esc、失焦或点击所有卡片之外时清理状态与计时器，松开快捷键不关闭。该机制不写数据库，也不扩大服务端授权的可见范围。

## 5. 条件执行与安全边界

### 共享地形合成与后台计算

`composeTerrainRegions` 先按地貌构造共享有符号距离场：同类笔迹取并集，后画的异类地形裁去先前对应部分，再从最终场提取轮廓。统一陆地底层填补地貌过渡带，地表颜料采用多级透明度与 SVG 高斯柔边；装饰从最终地貌归属采样，水域不会保留被覆盖区域的自动树木。树木成簇，山峰沿笔迹山脊安排，按垂直位置排列绘制。作者的区域源数据不被渲染算法修改。

`MapObject.blur?: number` 是 0–40 地图单位的可选柔边参数，缺省为锐利边缘。它同步进入严格校验、JSON/MySQL 往返、SVG 滤镜和 Markdown 属性摘要；原有 `editor_data` JSON 列足够，无需新增 DDL。生成结果转换和实际显示使用相同合成函数；隐藏区域另行冻结为隐藏对象。带孔填充通过零面积桥连接，描边必须使用独立闭环，不能描出连接桥。

`useComposedTerrain.ts` / `terrain.worker.ts` 把预览计算放到 Worker，只允许一个运行请求和一个最新草稿；中间过时草稿合并，返回值用请求编号关联。Worker 缓存未变源区域的采样结果，卸载时终止；无法启动 Worker 时才回退本线程计算。画布、指针与面板不依赖每次计算完成，绘制预览不进入工作区保存。最新结果未完成或出现合成错误时阻止导出，避免下载过时地图。

`map-brushes.ts` 保存 14 类笔刷预设和纯函数组件群组；语义水域影响聚落选址，人工矢量、旧随机底图不自动参与这一判断。`useMapStudio.ts` 仍负责交互事务、取样、键盘和撤销入口。

### 色块生成配方

`MapEditorData.generation` 是可选配方，缺省时继续使用原有 `composeTerrainRegions`。v1 为 `version: 1`、32 位非负整数 `seed`、`climate: temperate/dry/cold`、整数 `settlements: 0..12`、布尔 `rivers/routes`。v2 保留共同字段，使用 `version: 2` 并必填 `detail: standard/high/ultra`。服务端按版本严格校验，v1 不允许 `detail` 或新增地貌，v2 不接受遗漏/未知精度。区域原始几何、顺序与人工对象仍是持久化内容，配方不会覆盖它们。

v2 另有可选 `linework: 'organic'`，缺省时保持原 v2 河路线形；这是一项显式、可撤销的配方升级，不为已有地图注入默认值。新图及 v1 显式升级默认带此字段。服务端拒绝其他字符串/类型和 v1 中的该字段；JSON、MySQL 与 Markdown 同步，仍无需新 DDL。

服务端对配方执行严格字段校验，不接受未知算法版本或额外字段。`atlas_map.editor_data`（迁移 002）保存完整配方；海拔和分区沿用此 JSON 列，地图地理范围另由迁移 003 保存。MySQL、JSON 与 Markdown 摘要共享这一契约；Markdown 记录配方而不是整个派生网格。

`src/lib/sketch-generation.ts` 是版本分派入口；旧实现原样保留在 `sketch-generation-v1.ts`，v2 在 `sketch-generation-v2.ts`，网络算法在 `sketch-networks.ts`。旧地图只在用户显式升级后改变配方，升级可撤销；黄金哈希测试锁定 v1 原生成输出。羊皮纸展示配色另由下述适配层提供，不修改原布局。生成依赖为：

```text
作者色块 + 生成配方
       ↓
连续陆地/地貌意图 → 高程与坡度
       ↓                ↓
     气候与植被 ← 排水和汇流
       ↓                ↓
     适宜聚落 → 陆地道路
       ↓
可渲染与可冻结的 MapObject[]
```

生成器是无外部服务的确定性纯函数。v1 按最长边约 128 格采样，复杂输入最低 56 格；v2 为 192/288/384 格，默认 288，源控制点超过 6000 后随复杂度降低，最低 128。v2 将地图单位中的纹理/符号尺度与采样精度分开。对有序笔迹/多边形计算多尺度噪声陆地边界，后画水域优先；草原作为通用陆地意图可由气候推导地貌，其余显式地貌优先于气候。山地/丘陵/高原/荒岩贡献平滑衰减的高程场，低地噪声共享，避免仅因色块种子不同产生海拔接缝。雪原/苔原和湿地的高程影响也平滑过渡。

v2 的优先洪泛只填排水面，再选最陡的低邻格并累计汇流面积；原始高程不被改写。河网先抽取主河再展开支流，每个分支只入队一次；共享显示坐标使汇流连续。河宽与发源阈值按网格物理面积归一化，升高精度不会单凭格数让河流变粗。低平、近海、汇水足够且可下降至独立出海口时才添加少量分流；边界不连通的内湖不生成装饰性河口分流。显示只在受约束的走廊内平滑，支流末端沿自身宽度进入主河，不能突增为干流宽度。统计为“河段”，不是独立河流命名数量。

聚落按低坡度、适宜海拔、近水和间距选址，中心排除自动河道。v2 多源 Dijkstra 按坡度、海拔、地貌和空间变化代价寻找陆地道路，允许复用已有道路；只作局部圆滑，不再用全程可视线简化拉成直线。窄河允许有代价的横向跨越，并生成桥；道路固定锚与桥位复用河道显示坐标。每条显示路段需保持在可通行陆地，不连接隔海岛屿。

启用 organic 后，`sketch-curves.ts` 对寻路骨架采用按地图物理弧长的宽窗口平滑、低频侧向曲流与受约束插值。相邻固定锚点组成独立河路区间；周期上限为地图参考单位的 17/26 倍（河/路），在短段内收缩至区间长度的 1.05 倍；幅度上限为 3.6/2.8 倍参考单位，同时限于区间长度的 18%/14%。端点衰减范围取 2.6 参考单位与区间长度 18% 中的较小值，避免短支流被整体压直。最后使用四轮较轻的局部均值，保留宽缓曲率。小于等于 0.025 的轻坡不削弱河流弯幅，较陡位置逐渐减弱；岸水、相邻线段及高程检查仍保留，每次移动失败则逐级缩小。源排水树与海拔不改变，这只是制图显示曲线，不能解释为侵蚀或泥沙模拟。

汇流与分流连接点在所有相关河段中固定；道路保留聚落、桥头与共享路段锚点。曲流完成后，按每个网格边界精确切分显示线段，重建可见河格、最近河道位置、宽度与切线，供聚落选址和道路跨河使用。不能用固定步长采样代替这一步，否则短暂擦过网格角的河线会漏进掩码。organic 道路寻路和后续平滑都逐格检查，拒绝无桥穿河；桥位落在真实显示河段上。原 `diagnostics.rivers` 保留排水格骨架，不能拿它当新显示位置。

色块生成面板以有效陆地为开始条件；海拔模板可从无色块地图生成。面板提供选笔刷步骤、色块数量、草稿/预览、计算与错误状态。错误由 `MapArtwork` 回传到 `Atlas` 和侧栏；不能仅根据 pending=false 显示成功。自动选址会随新的可见河道变化，原色块与人工对象不变。暂未实现河路单独锁定、只重生成单条河或直接拖动生成河线的语义编辑。

地表是连续轮廓、低对比坡面、细等高线/排线、原创林冠、针叶林和不同地貌细纹。微小派生坡面噪声按面积过滤，连续填充先逐环简化、保留环方向与孔洞，再建立零面积桥；过长等高线按首尾共享的段拆分，不丢线。区域密度与总体装饰预算控制 SVG 复杂度；复杂到超过上限时仍明确拒绝，不能截断源创作。填充连接桥不用于描边。

`useComposedTerrain.ts` 与 `terrain.worker.ts` 在后台计算，过时结果与错误不发布，地图切换销毁旧 Worker。正在生成、失败、色块草稿状态均不能导出旧 SVG；草稿/预览开关只改变本地视图，不写入数据库。冻结使用相同生成器，并按地图 ID 派生对象 ID，防止不同地图同种子冻结后发生全局 ID 冲突；人工对象、隐藏源创作和标记保留。

派生地形与水系不创建世界实体或剧情内容。聚落数量是上限；狭小岛屿或不适合居住的区域可以少于请求数量。源区域锁定只限制直接编辑，不表示其派生内容不受全局气候、种子或邻近地形影响；人工细节需要转为独立对象后精修。

这一生成器面向世界/区域图，尚无板块、雨影、侵蚀、泥沙输送、湖泊出水系统或完整城镇街区模拟。网格分辨率以内的细节可能被忽略，平滑河流曲线是排水路径的显示近似，名称是可冻结后修改的初始标签。将来更改生成算法导致已有地图重绘时，应保留旧版本实现或提供明确迁移，不能无提示改变已保存创作。

### 海拔配方、重放与派生视图

`SketchGenerationV2.elevation?: ElevationSettings` 为可选海拔配方，v1 拒绝此字段。配方包含 `version:1`、`preset:sketch/continent/archipelago/highlands`、独立 32 位种子、`relief:0.25..2`、`seaLevel:-1000..1000` 与有序 `strokes`。每笔记录全局唯一 ID、`operation:raise/lower/flatten/smooth`、地图坐标点、直径 `5..500`、强度 `0..1`、定高目标 `-2000..6000` 米。严格校验非有限值、越界坐标、重复 ID、未知字段和容量（96 笔、每笔 256 点、总计 8192 点）。沿用迁移 002 的 `editor_data` JSON，无新 SQL DDL；存储往返/重启测试使用非空四类笔迹。Markdown 导出模板、参数和按顺序的笔迹摘要，JSON 保留完整配方。

`src/lib/elevation.ts` 是高程纯函数。处理顺序为色块基础高程 → 模板/起伏 → 顺序重放笔迹 → 减去海平面 → 更新陆海与岸距 → 原排水/植被/聚落/路网。无色块也能生成大陆、群岛、高地；`sketch` 则沿用原高程，独立地势种子只影响高程噪声，原生成种子继续控制岸线噪声与其他流程。启用中性 sketch（起伏 1、海平面 0、空笔迹）不截低旧高峰，也不扰动原几何。归一化高程乘 6000 作为虚构米数，非实测 DEM。

2026-10-05 修正非 sketch 模板覆盖色块高度的问题：采样源区域时构造派生 `TerrainHeightInfluence`（陆地/水域柔边权重、山丘与冷地隆起、高原、湿地）。模板基础起伏叠加局部隆起，约束高原/湿地，再按有序陆水笔迹权重调整岸域，最后应用起伏系数与海拔笔迹。未画区域仍保留模板，后画陆水在重叠核心区优先；海拔笔迹位于最后，允许在水域抬出岛屿或把山地挖成海湾。地形视图与海拔视图仅呈现同一组合结果，不分别启停其中一份数据。

模板把新格子变成陆地后，重新从显式意图恢复森林/山地等地貌；原水域被抬出则按气候与高度分类，草原仍表示通用陆地。新模板的刷区预筛选覆盖完整山脚作用范围，避免在旧 0.8 倍直径搜索框外突然截断；不改变无海拔配方和 sketch 的原搜索边界。领域契约和持久化字段没有变化，只修正派生计算。

每笔按格心到整条折线的最短距离作用一次，用平滑衰减函数淡出边缘；增加相同轨迹采样点不叠加强度。抬高/降低基准为每笔 1800 米乘强度和衰减；定高混合到目标（初始海平面基准）；平滑使用该笔开始时高度场的积分图求邻域均值，避免扫描方向反馈。实际修改值限制在 -12000..18000，未编辑的旧值不裁剪。陆海改变时重新计算有符号岸距，确保抬出岛屿/挖出海湾会进入成图；后续填洼仍只修改排水面。自动对象可以重新布局，人工对象、色块和标记不改写。

`ElevationField`（尺寸、Float32 高度数组、min/max）为派生数据，随 Worker 最新结果传递，不写入数据库。`buildElevationArtwork` 按高度提取带孔色带和等高线；`ElevationLegend.tsx` 在 SVG 内提供图例，`Atlas` 双线性取样读数。Worker 请求包含本地 `terrainView`，仅海拔视图计算额外等高图形；源草稿不渲染该视图，概览仍用古典画面。视图状态不进入 revision。

`ElevationPanel.tsx` 提供「地形 / 海拔」常驻切换入口。`terrainView` 既选择画面，也选择面板：地形页显示色块生成与地形/精修工具；海拔页显示模板、四刷和海拔参数，其他内容不挂载。即使没有 v2 也可以本地切页，实际海拔画面须等 v2 生成后才显示；此前保留原图并提供显式启用按钮。切页取消草稿、清空选择并激活对应工具，不持久化、不删除任一配方。海拔页的画布工具栏保留平移/标记和撤销重做，避免在隐藏属性下编辑地形。

`useMapStudio.ts` 负责预览和单笔提交。地貌色刷、海拔笔刷、群组共用 `radius`（历史变量名，实际为直径）；`elevationWidth` 是它的别名，范围 5..500，步进 5，键盘每次增减 10。`chooseBiome` 只更新地貌、密度与边缘起伏，不重设大小；旧 v1 的地貌回退同样保留直径。显式取样复制并限幅已有区域宽度，不改原区域。此偏好不进入数据库，手绘线条仍保持独立线宽。

`previewMap` 用 `useMemo` 保持稳定引用，避免 pending/高度回调的重新渲染重复排队同一草稿。拖动不保存，松手一次提交，Esc/指针取消不提交；限额提示明确。笔迹结果进入既有撤销、revision 和错误处理；撤销栈仍只在当前会话存在。停止海拔生成会移除配方与笔迹，按钮明确说明并允许撤销；冻结固定古典 `MapObject[]` 并移除配方，无论当前查看哪种视图。海拔图应先导出 SVG。

### 羊皮纸显示与导出

`MapPaper.tsx` 是概览与编辑画布共用的原生 SVG 装饰层：固定种子的 `feTurbulence`/颜色矩阵生成淡斑与细颗粒，叠加纤维、边缘旧痕、细边框和罗盘。每个实例使用唯一 ID，所有装饰 `pointerEvents=none`；位于地形/对象之后、旧手绘笔画、标记与编辑控件之前。色块草稿不显示此装饰，保持语义色易辨。纹理不依赖外部图片或全图 sepia 滤镜，不新增持久化字段；冻结时仍是显示层，不计入 8000 个编辑对象容量。

v2 的 `renderSketch` 输出浅暖纸底、灰橄榄植被与褐墨排线，视觉调整不改变高程、水路、聚落及主随机序列。2026-10-08 用户指出山脉密度低、峰形不好看后，`classical-relief.ts` 把基础候选间隔从最长边的 39/1000 缩至 24/1000，加入确定性位置抖动；区域 `density` 同时控制采纳概率与相邻峰间距。空间分块轮流选取高地，避免预算全部用于最高的一片山地；上限从 38 改为 144 个峰体锚点。以距离/高度差连接限度数森林图，深谷拒绝连边。按每棵树最长主干分解连贯范围与支脉，共享山脚淡彩、相邻峰体及鞍部。

`mountain-styles.ts` 现提供 128 种实际轮廓：高、中、矮、极矮各 8 个基础结构 × 4 种肩部/岩脊处理，共 32 种/档。32 类原始轮廓各自定义，四种处理改变断肩、凹槽、肩峰、偏置及支脊，不把随机宽高或镜像算作新样式。归一化后每种轮廓仍不同；圆顶/缓丘做折线细分平滑，尖峰/断崖/台地保留折角。所有天际线 x 单调、归一化 y 在 -1..0，岩脊约束在自身轮廓下。`assignMountainStyles` 按归一化高程 0.68/0.48/0.32 分档，各档 32 种全部取用后才复用，同时惩罚附近同形/同家族，独立散列不消耗地理 RNG；这些是插画分类阈值，不是统一真实海拔标准。

为表现山脚，候选下限从 0.39 降至 0.18；低于 0.39 的非山地/丘陵/荒岩，须在 65/1000 最长边范围内有更高地势，避免给无关平原铺满丘陵。优先给主山体约 74% 锚点，低丘填充剩余，余量再给主峰；区域平均密度也缩减锚点预算，避免拓宽候选范围后低密度仍触顶。极矮丘陵（<0.32）不连斜视鞍部，避免低缓凸起之间拉出长坡带。深谷与陆海检查继续保留。

`mountain-artwork.ts` 统一投影与钢笔淡彩绘制，供真实生成和 `MountainStyleGallery.tsx` 共用；每峰最多 14 个普通路径/多边形。按地面 y 遮挡，宽高仍有确定性变化，纸色三层向山脚淡化、灰褐背阴；低丘使用更疏的线和更浅的阴影。排线沿真实肩部弧长弯曲、尖细化，分叉支脊和每面小闭环由往返零面积桥合成填色多边形，无可见桥线或新增字段。笔线两端精确归零，正弦开方前夹至非负，避免浮点舍入产生 NaN。岸边峰体整体缩小拟合，每条边与面仍检查陆地。

`renderSketch.objectCount()` 只在内存中用于容量计算。河流两层、道路（含长路径分段）、桥栏和聚落最大细节先预留对象空间，再生成完整山体并预留其实际对象数，最后按剩余容量调整植被装饰概率。山脉绝对上限 4200 对象，覆盖尺度还限制预算与锚点数，400 km 基准最多 144 峰；每锚点最多 20 个对象，包含新增遮挡底色、完整峰体、森林边和共同山脚。预算不足减少完整峰体组，空间轮选保留多处高地，不截断半个山体，也不让森林细节挤占世界地图所需的密集山脉。全图上限仍为 8000。独立散列不消耗地理随机流，平坦高原不虚构峰顶，零密度不生成山脉插画。

绘制顺序为地表与植被、河岸与水面、道路与桥栏、山体、聚落。每个峰体先画普通不透明多边形「山体遮挡底色」，鞍部使用无填充淡线连接，再叠淡彩、排线与峰谷轮廓；山脚外侧的淡彩仍透明。这样河路在山体背后消失，在空隙/谷地保留，而不是透过半透明山面。底色和顺序随普通 `MapObject` 冻结、保存、JSON 与独立 SVG 保留，没有额外 CSS 遮罩或数据库字段。完整排水/道路几何仍在下方，遮挡本身不裁掉网络、不改变真实高度或流向；人工覆盖层与旧自由笔画仍依作者图层排列。

自动峰体名称带可读样式与稳定目录 ID，最后一段仍是岩面部件名；冻结/JSON/Markdown 沿用原名称字段。`MapObjectArtwork` 从名称解析 `data-relief-part` 和 `data-mountain-style`，仅为浏览器定位/验收，不是新领域字段，人工重命名不改变几何。`MountainStyleGallery` 使用共用 Modal，四档各显示 32 个同尺度预览，切档/关闭为本地状态；地图、独立图鉴、冻结和 SVG 共享绘制函数。上述山峰样式和遮挡不新增领域字段或 SQL 列；当前组件与图片契约扩展见后文。旧 v1 和未启用新版配方的普通合成保留原算法；v2 动态画面随构建刷新更新，128 峰形和遮挡本身不改高程或作者资料，已冻结和人工对象保留。覆盖范围的地势与网络分配及海拔配方是独立生成步骤，见相应章节。

`map-palette.ts` 将 v1、普通地形合成与旧随机底图的自动配色适配为羊皮色，`MapArtwork` 与 `bakeMapArtwork` 使用同一适配，避免冻结后换色。原 v1 生成器与黄金输出保持；作者的 `editor.objects`、`map.strokes` 和已有冻结对象不重新映射，避免碰巧相同色值的手绘被改写。旧底图转换原有的符号/纹理简化仍存在，不承诺逐像素无损。

SVG 导出克隆当前 SVG，保留纸张 defs/滤镜/路径，通过 `[data-map-viewport]` 精确移除平移缩放，而不是假设第一个 `<g>` 就是视窗；继续去掉编辑命中层/控件。概览也绘制旧手绘笔画。纸纹与装饰当前是固定画风，没有可调强度或可编辑纹理控制点。

### 轻量草稿与指针预览（2026-10-08）

`MapArtwork.SourceTerrainArtwork` 与 `ComposedTerrainArtwork` 是互斥组件：色块草稿不调用 `useComposedTerrain`，因此切换会终止正在计算的 Worker，首次无配方也可使用。`SourceRegion` 按笔迹对象引用 memo，历史路径不随鼠标重算；`Atlas` 隐藏底图、纸纹、原组件、旧笔画和人文遮罩，保留原数据。原底色查找 memo；退出草稿后恢复全部内容。初始引导的画陆地/添山林主动进入草稿，地形效果仍可预览；草稿无配方提交不在主线程合成地形，派生合成失败随后由预览显示。

`useFrameState` 只合并绘画预览和光标，每帧至多发布一次状态；真实指针采样始终同步进手势 ref。松手从 ref 提交，空值清理立即取消待执行帧，避免 Esc/释放后冒出幽灵笔迹。主编辑器、分区预览均使用，细笔刷采样间隔最低 1 单位。保存与 revision 不由预览驱动。

### 分区吸附与快捷创建（2026-10-08）

`MapArtwork` 从已完成的渲染结果返回海岸；新生成用「沿岸浅海」闭环，共享融合用「陆地 · 共享地表」，旧随机底图和冻结的大陆多边形也可提供轮廓。`land-snap.ts` 先拆开复合多边形的零面积桥，建立分段空间索引，忽略人为画布边缘；每笔范围的实际轮廓按最大距离投影到最近海岸/湖岸，并局部沿岸插点，避免跨湾直弦。再按环简化、检查交叉/坍缩与孔洞包含关系，合并桥。只替换目标笔迹，保持 paint/erase 和原占据次序；复合飞地需要时拆成连续同位记录。所有容量验证通过后一次提交，否则保持原图。沿用 `DivisionPaint` 与 JSON 列，无新 DDL；普通渲染、Markdown、JSON、SVG 沿用同一边界契约。

最大距离为绘图单位，按可选 km 范围提示物理距离。它只调整近岸范围轮廓，不自动填满大陆、推演政治边界或限制全部领海。冻结后改名/删掉已识别海岸组件会失去其语义，任意手绘图形不猜作海岸；多层手工叠加也不是完整 GIS 布尔裁切。复杂度过高或吸附会变坏时拒绝整次操作。

`DivisionQuickCreate` 复用可聚焦/Tab 循环/Esc 的 `Modal` 和 `newEntity` 模板，只在确认后提交。国家仍是 faction，其他两类各用自己的 EntityType。`App.onCreateDivision` 以一次 setData 同时添加条目和地图关联，避免自动保存先看到悬空引用；地图撤销可移除关联，已创建档案保留。名称重复/空白及分区数量超限可见提示，取消无保存。

### 条件引擎

纯函数读取变量快照，按受限运算符判断条件；不触发网络、文件系统或数据库副作用。效果由已校验的数据描述，GM 明确执行后才修改变量。状态更新与变量更新作为同一工作区变更保存。

`src/lib/plot-engine.ts` 的前驱规则是：无入边可开始；有入边需至少一个前驱已完成。随后按 `conditionMode` 检查变量条件，无条件视为通过；已完成节点不可再次执行。字段 `status` 与推导的可用状态需要在 UI 中清楚区分，不允许仅把节点标成 available 就绕过条件。

单作者版的 `public/gm` 是作者整理和导出策略。生产登录保护整个工作区；在没有服务端玩家视图 API 前，不可把工作区返回给玩家后仅靠前端隐藏 GM 内容。未来多人权限必须同时保护搜索、摘要、图节点、地图标记、导出和原始 API。

生产环境强制鉴权与 MySQL；演示模式必须显式开启并标记。Cookie、登录频率限制、跨源请求、上传验证和秘密管理的具体机制以服务器实现为准，交付前检查配置示例。

当前生产要求同时配置 `APP_PASSWORD` 和 `DATABASE_URL`。开发环境缺少数据库连接时进入明确标识的 `data/demo-workspace.json` 模式。登录使用签名、HttpOnly、SameSite=Strict 的 12 小时会话 Cookie；失败登录限速 15 分钟内 10 次。`SESSION_SECRET` 未指定时随机生成，重启会使现有会话失效；会话当前保存在进程内，不支持多个应用实例共享登录。

上传仅接受 PNG、JPEG、WebP，检查文件签名与 MIME；上传资源访问也需要会话。生产 Cookie 默认 Secure，部署到本地 HTTP 时需要明确设为 false。`TRUST_PROXY` 只适用于已配置的单层可信代理，代理应保留 Host。

## 6. 可迁移性

### 地图尺寸与人文疆域（2026-10-08）

`AtlasMap.width/height` 为 100..10000 整数绘图单位；新增可选 `scaleKm` 为横向地理范围 0.01..1000000 km，纵向由宽高比推算。迁移 `003-map-scale.sql` 增加 `atlas_map.scale_km DOUBLE NULL`，schema 锁内检查列类型、空值与版本，可恢复 ALTER 后尚未记录版本的状态。旧 NULL 读取时省略字段，不回填、不改 revision。仅对已授权专用项目库执行；数据库迁移号 3 与 editor 数据版本 1 无关。

`map-scale.ts` 集中管理预设、距离显示与 `resizeMap`。改变画布同时按 x/y 比例缩放所有人工坐标；宽度、尺寸、线宽及模糊按几何平均比例调整并限于各自合法范围。非等比例画布会拉伸形状；生成内容重算、人工对象不裁切、ID/关联/种子不变。尺寸修改为单次可撤销工作区更新，继承现有 revision 事务语义。

新建世界/区域使用 v2 organic + continent 海拔模板；城镇默认仍使用现有街区示意底图，启用 v2 地形后也可使用以下细节规则。`mapDetailProfile(scaleKm, kind)` 优先读取显式 km 范围，缺省按世界 12000 / 区域 400 / 城镇 10 km 估算；独立库函数没有地图上下文时保持 400 km 中性默认。地图类型随 Worker、回退、概览与冻结一起传递，并进入最新请求/过期结果判定。已有缺省范围的动态 v2 现在随类型读取细节；v1、冻结几何、人工笔迹和标记不自动改写。

局部生成单位、植被/聚落尺度使用 `(400 / km)^0.18`（0.65..1.6）；山峰的宽高、采样间隔、邻域和连边尺寸使用 `(400 / km)^0.17`（0.55..1.6），锚点数量/对象预算随范围反向调整。河流的汇水阈值乘细节尺度平方（修正先前反向除法），较大范围显示更多源流与支流，河段数量预算和近海分流预算也随尺度变化；河宽同时随范围和画布长边/1000 缩放，采样加密不使水系变粗。道路继承细节尺度线宽，较大范围在连通主干外增加经过相同地形/桥梁搜索的区域连接，至少 12% 且不少于 3 个网格边为新走廊，不能只是重描已有道路；不虚增用户指定的聚落上限。海拔、河谷、水面、桥宽与过河方向约束继续有效。

显式范围且画布长边超过 1000 时提高地形采样，最大 512 格，复杂色块仍会下调。比例尺按 km/画布单位计算，旧图明确标记估算；海拔米数仍是设计尺度。范围规则是示意制图细节分配，不是物理降水/交通容量或真实城市街区模拟。

`MapEditorData.divisions?: MapDivision[]` 与 `divisionPaint?: DivisionPaint[]` 保存疆域：分区有 id/kind/name/entityId?/color/visible；笔迹有 id/divisionId/operation/geometry/points/width/roughness/seed。三个 kind 为 country/culture/religion；对应条目类型 faction/culture/religion，必须同世界。国家复用势力条目，不新增实体枚举。解除关联或删除条目保留疆域，界面可重新关联；删除分区及其笔迹不删除条目。条目默认名称随改名更新，作者另取的分区名称保留。

`divisions.ts` 复用连续距离场与轮廓采样构建弯曲笔刷和圈选边缘，圈选起伏为 0 时保留精确多边形（SVG 坐标两位小数）；`useDivisionStudio.ts` 在拖动时只生成本地草稿，松手写一笔，Esc/失焦取消。每层独立，paint 最后占据，erase 仅清除当前分区且不恢复先前占有者。`MapDivisions.tsx` 用同一 cutout 的 SVG 定义和引用组成有序黑白 mask，邻居共用边界、孔洞由同样的擦除形状保留；浅色罩染与细边框保留羊皮地形可读性。隐藏分区不释放土地；当前浏览器主题与工具选择不写入工作区。支持控制点拖动/数值/插入/删除、已有笔迹边缘起伏、颜色与显隐；标签复用无需快捷键的延时、锁定摘要组件。

服务端严格校验 96 分区/256 笔/每笔 256 点/总计 16384 点、所有 ID 和坐标及对应实体类型，限制未知字段。JSON/MySQL 保存完整几何，Markdown 仅摘要与关联并排除玩家版中关联 GM 条目的分区；SVG 输出当前主题可见分区，编辑手柄剔除。没有自动推演政治边界、沿河/山脊吸附或 GIS 球面投影，分区允许作者覆盖海域；最大容量浏览器性能尚未压测。

- Markdown 是阅读和分享格式，适合部分或全部内容；不承诺导回后恢复所有图形编辑状态。
- JSON 是领域结构备份；恢复前执行与普通写入一致的引用校验。
- 历史 JSON 没有 `AtlasMap.editor` 仍有效；新备份中的 `editor.version` 必须受支持，不对未知格式进行有损猜测。
- 图片上传存独立资源目录，JSON 中仅有引用；搬迁还需同步该目录。
- MySQL 备份用于完整运维恢复；环境变量保存连接与鉴权配置。提供 `.env.example`，真实 `.env` 不进 Git。

## 8. 浏览器回归测试隔离

### 构建更新与地图配方

页面构建版本与地图生成配方版本独立。Vite 生产构建向 HTML 注入 `worldloom-build` meta，并输出同一随机构建 ID 的 `app-version.json`。HTML、固定版本清单使用 `Cache-Control: no-store`；缺失清单返回 404，不回退 SPA HTML。带 meta 的页面在启动、重新获得焦点、变为可见以及每 60 秒检查清单，10 秒请求超时；离线/格式错误静默忽略，隐藏页不轮询，无 meta 的开发页由 HMR 管理。

新版可用时只提示，不自动刷新。`useWorkspace.setData` 同步更新当前快照引用，`reloadWhenSaved` 在用户点击时再次检查当前与持久化快照相同、无在途保存/冲突、状态为 saved 以及没有编辑器草稿，避免依赖异步状态提示而丢失尚未提交的修改。刷新不更改任何地图配方。

`Atlas` 在画布上方显示生成方式，v1/旧 v2 提供「启用新版河流与道路」，按现种子启用 organic。`useMapStudio.regenerate(seed?)` 统一显式重生成：传入 seed 则指定，无参数则换种子；v1 使用 v2 high organic，旧 v2 保留精度并启用 organic，保留共同配方、原区域与人工内容。侧栏旧配方按钮标为「重新生成（新版）」；地图档案有配方时从 `generation.seed` 读写，调用同一入口，不再改不可见的 `map.seed`；随机底图开关在此时隐藏。无配方时保留旧底图操作并明确命名。全部走同一撤销/保存队列；仅打开旧图不升级，停止后再启用则使用当前生成器。旧页面最初没有更新检测代码，首次部署该功能仍需手动刷新。

## Windows 桌面附加包

登录开关保存于 installation.json 的 loginEnabled，旧配置缺省为 true；凭据仅在开启时必须存在，关闭的新安装不生成账户或密码哈希。Auth.required 采用受管理安装的显式开关，不被继承 APP_PASSWORD 意外覆盖；免登录请求仍走所有服务端验证，以 owner 身份执行。安装时用户目录先原子准备，安装配置提交失败则回滚目录，不成功就不返回成功；多用户选择和登录校验在创建存储之前完成。

后台 PUT /api/admin/login 仅主管理员可用；开启要求新登录名/密码，关闭验证当前密码并拒绝已开启多用户。登录变更、用户模式与用户名写入共用 InstallationManager 配置队列，执行时重验身份，避免并发开启多用户/关闭登录或抢占用户名。多用户改变清除其他账户会话，登录策略改变清除全部会话并重新建立当前主管理员会话；创作库和 revision 不受策略修改影响。免登录的私有备份下载保留显式确认，不能再要求不存在的密码。启动发现“多用户开启但关闭登录”的不一致配置会拒绝服务。

shared/plate-names.ts 使用独立的确定性文字名映射，不消费地形随机数。新板块直接生成文字名，历史数字默认名仅显示转换；地图标注、图例、编辑列表和 Markdown 共用同一规则，保存自定义名称后重构按板块 ID 保留，不重算原图。

`desktop/main.cjs` 提供 Electron 独立窗口和原生菜单，渲染进程关闭 Node 集成、开启上下文隔离和沙箱，不提供通用 IPC。仅加载已选本机工作台的 origin，阻止任意外部导航和弹窗；导出使用原生保存窗口。名称取自 shared/brand.json，图标由现有 favicon 矢量渲染。

`desktop/service.cjs` 管理相同 Node 后端：从干净 resources/backend 模板复制到全新的同级临时目录，再原子改名为 workspace；已有实例绝不被模板覆盖。内置独立 Node/npm 和生产依赖，初次使用不执行联网安装。继承环境中的数据库、数据目录、Node 注入与旧更新身份变量被移除；选择的工作台私有配置及固定 dataDir 仍生效。桌面自己启动的服务仅监听 loopback。

已有服务必须以所选目录的控制钥匙完成健康确认才附接；持久 PID 不作为停止权限依据。附接服务的窗口退出不发送 shutdown。自己启动的服务经受保护接口正常停止，并等待固定启动器退出；挂起/运行更新任务时拒绝中断。后端依然执行登录、模块/逐条权限与 revision 校验，桌面不绕过主管理员授权。

桌面 ZIP 是额外发行，原 CMD/服务器和其他系统包保留。桌面壳升级与 workspace 内受签名后端更新分开，不能删数据或自动覆盖旧 workspace。源码构建、保护单测、原生 GUI 与 CMD 附接测试见 docs/desktop.md；测试只在 .runtime 下新建合成 SQLite 实例。beta.19 起提供下节的桌面壳自动升级；商业代码签名、系统安装器和全部断电场景仍未完成，不把这些能力一并视为已经实现。

## Windows桌面程序自动更新

原生帮助菜单由Electron主进程控制，不向网页开放通用IPC。每次检查与安装前读取当前浏览器会话身份并要求主管理员；开启登录时未登录、次级管理员、普通用户或未保存编辑拒绝安装，免登录模式仍采用服务端的owner身份。原workspace后端必须先升级到beta.19以提供桌面维护租约；配置端点404明确拒绝并提示先升级后端，不回退成无租约更新，401/403同样拒绝。独立Node子进程运行scripts/desktop-update.ts，复用HTTPS公网/DNS固定/限跳/流式下载器；后台128MiB上限保持，桌面显式512MiB。独立Ed25519描述绑定ZIP、版本、最低壳版本、全部文件树和三个启动组件，唯一公钥源shared/release-trust.json；镜像不能改变信任。

ZIP在新建.desktop/releases/shell-UUID/app中解压，PowerShell/.NET先检查全部路径、设备名、大小、重复及链接再写，拒绝workspace/.desktop/data/账号/私钥等，完整树与签名一致才准备成功。旧EXE与工作台不被替换，原.desktop/settings.json与workspace指针保留。下载可取消，验签/备份后等待；独立程序门和active-job记录阻止并发。

完整备份恢复验证后正常关闭自己拥有的后端；附接外部服务只释放自身维护门，不停止该服务。独立helper等待旧PID退出，不强杀，再启动已验证新版；新壳确认随机nonce、原workspace、账号/授权摘要与不降低的revision后才原子提交current-shell指针。完成后旧入口代理到新版本。失败不恢复任何世界旧快照，保留原指针；若失败新窗口仍活着需先关闭再重开，避免强杀。挂起/断电的所有组合未完整验收，旧版本与备份不自动清理。

发布者在完整桌面ZIP逐文件验证后运行scripts/sign-desktop-release.ts生成同名.update.json；不带私钥、用户目录或更新任务。它与后端.ccupdate是不同包，Docker不使用桌面更新器。

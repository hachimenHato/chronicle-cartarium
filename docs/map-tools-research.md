## 2026-10-08：128 种高低峰形

用户继续要求一百种以上的样式，覆盖高、中、矮和极矮，并减少重复感。本轮基于既有钢笔淡彩选型做原创结构目录，不新增外部素材或宣称竞品操作实测。32 类基础轮廓分别定义，包含角峰、双峰、复合峰、锯岭、偏峰、圆顶、台地、断崖与丘陵；四种肩部/岩脊处理改变凹槽、分叉和偏置，共 128 种，四档各 32。缩放和镜像不计入数量。

真实生成按地势选档、各档轮取并惩罚近邻重复，补充低缓山脚并避免极矮丘陵连出夸张坡带。图鉴与地图共用程序化绘制；已查看全部 128 种和真实地图只读预览，具体样例、完整性和持久化检查见开发日志。样式数量与几何区分度可验证，画面美观仍需用户使用反馈。

## 2026-10-08：山体密度与轮廓修订

用户明确否定了上一轮山脉的密度和外观。此前最多 38 个锚点、较大纵向间距和相似的三角峰面，使广阔高地空洞、重复；自动化通过并不代表画面获认可。继续依据下方已查阅的古典钢笔/连续山脊教程，重视峰群遮挡、主峰与肩峰差异、山脚渐淡；此轮没有重新宣称竞品操作实测或使用教程图像。

本项目实现判断：物理间隔缩小、上限改为 144，并按空间分块轮流取峰，现有区域密度同时影响采纳与间距。宽高、偏斜、四类肩部轮廓及位置抖动改变峰形和排列，主峰、肩峰、共同鞍部和山脚相连。弯曲尖细排线按面合并为普通填色多边形，增强背阴与遮挡，同时先给河路/聚落预留对象容量。高度与水系不由插画改变。

已用同种子高地、色块生成和用户最近的 1600×1000 地图制作只读预览；真实源数据没有修改，实际图像和检查结果见最新开发日志。画面仍待用户判断，不能将“更密”和“冻结不丢细节”当作手绘艺术质量证明。

## 2026-10-08：此前连续山脉与近岸编辑

用户指出象形山峰堆积仍不好看。本次改从“反复放置峰图形”转为“描绘一条连贯山脊及它两侧的坡面”。国会图书馆收藏的 1865 年北卡罗来纳/田纳西山地地图用晕滃线表达地势，并同时组织水系、道路与州界，提供了连续线条和信息层次的参考。[馆藏数字地图](https://www.loc.gov/resource/g3900.cw0079a60/)；该图属于近代历史地图，不能据此声称复原中世纪制图。

本项目的设计判断是：剑与魔法世界可用较浅纸底、褐墨连续山脊、渐细坡线和克制明暗获得古典阅读感。实现从实际高度/局部起伏筛选锚点，连接与平滑山脉，再绘坡面和晕滃；没有复制馆藏图像、竞品图章或算法。图形仍可冻结成矢量组件精修，水系与地理随机流保留。效果已查看实际生成截图，但美术是否满足用户要求仍需反馈。

编辑层面采用草稿与成图分离：草稿完全不挂载生成 Worker，完成意图后再看成图；首次色块也适用。人文疆域仍由作者划定，增加有最大距离的最近海岸吸附与地图内创建条目。这是本项目的流程取舍，不宣称已具备成熟工具的政治、文化或宗教自动传播模拟。

## 2026-10-04：古典地图表达与海拔编辑

用户在羊皮纸版本之后要求更接近专门的古典地图，并能生成、编辑海拔。本轮将画面表达与地理数据一起调整：浅纸色承托墨线，山峦由高度场决定位置，编辑高低会重新影响陆海和自动水路。下面区分外部资料、项目设计取舍及当前实现；浏览器与数据库实测结论以本轮开发日志为准。

### 一手资料与设计依据

- **Azgaar 高度编辑。** 官方文档把高度图作为可编辑数据，提供模板、升降与平滑笔刷、等高线和排水预览，并区分修改高度后重建或保留其他地图数据的模式。这支持本项目采用“高度来源 → 有序编辑 → 重算下游内容”的流程，而不是在旧地图表面叠一层颜色。[Heightmap customization](https://github.com/Azgaar/Fantasy-Map-Generator/wiki/Heightmap-customization)
- **历史地图的象形地势。** 美国国会图书馆所藏《Americae sive novi orbis proximarvmqz regionum orae descriptio》著录年代为 `[1602?]`，明确记录地形以象形方式表达。它是早期近代地图参考，不是对中世纪地图年代或测绘精度的复原依据。[馆藏著录](https://www.loc.gov/item/2006627851/)、[数字地图](https://www.loc.gov/resource/g3290.ct007262/)

据此作出的美术判断是：地图的古典感主要来自清晰岸线、连贯的象形山峦、迎光与背阴面的刻线、克制的洗色和边饰。将整张图染黄或继续增加模糊，容易让山地、森林和纸面混在一起。本轮采用较浅的纸色，降低旧痕与大块地貌阴影，新增不规则峰面、背阴、山脊及短排线；平坦高原不因海拔高就凭空长出密集尖峰。纸纹与边框是展示层，手工选择的对象颜色仍保留。这些是本项目的原创绘制规则，不是照搬历史地图像素、竞品源码或素材；没有把外部地图图片加入应用资产。

象形山峰也不能代替实际高程。项目中的高度网格先接受模板和笔迹修改，再参与坡度、陆海、排水、河网与道路生成；古典山形只是该数据的二维表达。山形绘制检查完整范围是否位于陆地，河路与聚落再叠于其上。编辑海拔可以移动海岸并重排自动生成内容，已有手绘对象、笔画和标记保留；因此不能声称修改地势会自动迁移所有人工标记，或完全保持原有自动聚落位置。

### 本项目的实施建议与验收方式

以下是结合上述资料与现有规则网格作出的设计判断，不是对竞品内部实现的转述，也不是完成声明：

1. **保留排水关系，单独构造自然河线。** 沿弧长采样，采用连续、低频的侧向变化形成宽缓弯道；平原允许更大弯曲，陡坡和狭窄谷地减弱。源头、汇流点、河口固定，共用的河段只生成一次；靠近其他河道、海岸和地图边界时收敛偏移，避免视觉穿越和回头自交。升分辨率不能让弯道振幅缩成一个格子。
2. **道路寻路后再作受约束的曲线拟合。** 地形代价决定大方向，在可通行走廊内软化转向并消除长距离网格轴线；聚落、路口和桥头保留锚点。拟合后的整条段落应检查湖海与不允许穿越的水道，失败时局部缩小偏移。不要对每个点独立抖动，也不要要求所有道路具有相同正弦波。
3. **先提供好用的默认值，再提供少量意图预设。** 简单层突出“画色块—生成—调整”的当前步骤；适合用河流弯曲程度、道路走向这类可理解控制，而不是要求用户理解插值参数。快速预览与最终细节分开，计算期间保留上一个有效画面并明确提示；已有人工内容继续受到保护。
4. **把局部重做列为后续明确能力。** 分别重做河路、固定喜欢的生成结果、直接拖动河线/路线的少量控制点都有价值，但需要持久化连接与锁定语义，不能用一次冻结整个地图冒充局部可控生成。实施状态以开发日志为准。
5. **同场景比较全图与放大图。** 固定种子检查平原、山谷、绕湖道路、汇流和桥梁，比较曲线连续性、直段比例与是否越界；同时走一遍首次创作和参数修改。几何指标用于发现退化，视觉截图用于判断线条是否柔和，最终仍需要用户判断美感。

优先级是自然河路和可靠的默认生成体验。新增更多地貌或继续提高采样，不能单独解决直线与生硬转角。

## 最值得参考的六组工具

### 2026-09-29 水系规则核实

USGS 对流域的说明强调地表径流汇向共同水系；河网分支首先应表现上游支流汇入主河，而不是任意方向画叉。[USGS 流域与排水盆地](https://www.usgs.gov/water-science-school/science/watersheds-and-drainage-basins)

USGS 的三角洲研究区分汇流和下游分流，分流受水与泥沙及下游边界条件影响。[USGS 三角洲分流研究](https://www.usgs.gov/publications/mechanics-flow-and-sediment-transport-delta-distributary-channels) 本项目据此作设计简化：只在低平、靠海且存在下降出海路径时生成少量分流；未实现水动力或泥沙模拟，不能把这一规则生成称为真实水文模拟。

### Azgaar 的补充研究与本项目取舍

Azgaar 的高度图模板由抬升、凹陷、山脉、山谷、海峡和平滑等步骤组成，可用种子复现同类地图；高度编辑与最终世界数据分开，修改时要考虑重生成数据和保留数据的不同后果。这两点直接指导本项目：色块先形成地形约束，水系等下游内容再依赖地形生成；作者输入与自动结果分别管理。[模板编辑器](https://github.com/Azgaar/Fantasy-Map-Generator/blob/master/docs/wiki/Heightmap-template-editor.md)、[高度图编辑](https://github.com/Azgaar/Fantasy-Map-Generator/blob/master/docs/wiki/Heightmap-customization.md)

本项目自行实现简化的语义场、高程、排水、植被和聚落道路规则，不复制 Azgaar 源码或声称具备其全部能力。也不要求初学者直接操作高程数值：草原表达一般陆地，山地表达抬升，水域表达水面，森林/沙漠/沼泽/雪原表达地貌偏好，再由气候与地形补充其他内容。算法版本、种子及输入保留在地图中。

全部参考仍有分工：Inkarnate 的画面和材质、Wonderdraft 的大陆与山林绘制、Dungeondraft 的材质交错、Azgaar 的地理依赖、Watabou 的城镇结构、Dungeon Alchemist 的按用途布置。第一步聚焦区域图生成闭环；详细城市与室内生成仍是后续独立工作。

## 地形融合到底应参考什么

Dungeondraft 作者文档明确说明：地形使用无缝纹理，PNG 的 alpha 可以表达材质相对深度，另一种地形覆盖时先进入低处。它用裂土地面作例子，裂缝先被填充，再覆盖较高处。这是有细节的交错过渡，单一颜色的透明渐变无法完整表达。[来源](https://github.com/Megasploot/Dungeondraft/wiki/Custom-Assets-Guide#terrain)

结合 Inkarnate 官方教程主题，9 月 27 日提出以下视觉目标；本轮实现部分连续地表、坡面、林冠和水系，完整材质与风格目标尚未完成：

1. 草地与泥土边缘保留斑驳和草簇，让交界有宽度及不规则细节。
2. 森林由中心的密集树冠逐渐过渡为疏林、灌木和草地；对象尺度、遮挡与阴影保持一致。
3. 山地有主脊、次峰、山麓和裸岩过渡；不把所有峰作为等大的孤立符号散开。
4. 岸线同时考虑陆地轮廓、浅水、岸边材质和浪线；海岸、湖岸与河岸不强制共用同一装饰。
5. 道路和河流沿连续路径变化宽度、处理分叉连接，并与周围地面产生合理过渡。

不能从竞品的公开成图反推出具体算法，也不能把本轮的简化实现等同于完整支持以上美术目标。

## 编年图志的现状判断与建议

当前共享地形场解决了同类笔迹合并、地貌覆盖和部分接缝问题；单元和浏览器测试验证了行为、保存与导出。**用户仍不认可最终画面，因此地图美术验收尚未通过。** 测试通过不能替代用户对好用和美观的判断。

目前主要差距是材质细节、成套素材的美术一致性、不同尺度下的空间组织和完整创作流程。继续增加模糊半径或更多孤立图章，难以单独解决这些问题。表现质量也不只取决于 SVG 或位图格式：Watabou 的简洁表现值得参考，具体渲染技术应服务于选定的画风和编辑体验。

### 参考优先级

1. **画面与基本绘制：Inkarnate + Wonderdraft。** 先明确世界/区域地图的视觉目标，建立一套完整的材质、山林符号、海岸和文字规范。
2. **地形交界：Dungeondraft。** 优先验证草地、林地、山麓、湖岸的衔接；大地图与局部地图分别采用适合其尺度的细节。
3. **生成与城镇：Azgaar + Watabou。** 自然地理与城镇布局分别建立语义结构，不能让同一随机散布逻辑承担所有地图类型。
4. **智能布置：Dungeon Alchemist。** 用区域用途和空间约束组织组件，并保留逐个精修的能力。

### 与用户要求的三级工作流对齐

| 级别 | 建议的用户动作                                 | 工具应负责的工作                                            | 主要参考                                |
| ---- | ---------------------------------------------- | ----------------------------------------------------------- | --------------------------------------- |
| 简单 | 选风格，涂陆地/水域/山林意图，选种子           | 自动生成连贯地形和成套画面；提供少量可靠预设                | Azgaar、Wonderdraft                     |
| 智能 | 改山脊、河流、森林边界；圈出城镇区域、指定用途 | 重新组织选区内地形或建筑；尽量保留已锁定细节，并可预览/撤销 | Wonderdraft、Watabou、Dungeon Alchemist |
| 精细 | 编辑材质遮罩、路径、单个对象和文字             | 提供明确的选择、图层、对齐、局部擦除与数值控制              | Inkarnate、Dungeondraft                 |

以上是下一版设计建议，不是重新定义已经完成的功能。三个级别继续共享创作数据，局部重生成不能静默覆盖人工内容。

### 下一次实现前的具体样例

建议先做一张小型区域图作为视觉样例：海湾、沿岸平原、树林、连贯山脉、入海河与一座聚落。用同一画面同时检查整体构图和局部放大，并记录从空白到成图的实际操作步骤。检查重点为地形是否自然衔接、符号是否有统一风格、文字是否清晰、局部修改是否容易。

城镇另做道路—街区—建筑样例；不要用世界地图的图章密度代替城市布局。视觉目标得到用户认可后再扩展组件数量和更多场景。后续仍保留持久化、撤销、兼容、导出和性能验证，但不能以这些检查替代视觉验收。

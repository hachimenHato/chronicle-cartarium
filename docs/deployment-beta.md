# 0.2.0-beta.6 安装与部署

本版正式更名为“编年图志 Chronicle Cartarium”，四字中文及英文在安装/登录/导航/导出/启动和发行中统一。beta.5可以用原启动器和签名直接更新到beta.6；旧JSON/归档、原数据库与卷、数据路径和账号保持兼容。默认旧标题显示为新名称，私人配置和自定义标题不批量改写，详见[名称兼容说明](branding-compatibility.md)。

beta.5增加完整私有备份/副本恢复验证、固定安装根启动器和受签名离线程序更新，保留既有地图和创作功能。没有新增数据库迁移；已有安装保留配置、账户和数据。更新的用户操作为“选择更新包 → 备份并更新”，详细范围与限制见[更新与恢复指引](update-strategy.md)。JSON/MD只含创作与图像引用；.ccbackup才包含数据库、账号、权限及上传原文件。

## 本机首次使用

Windows发布目录已捆绑当前验证的Node22.18与npm，双击 `start.cmd` 即可准备依赖并启动；首次准备依赖需要联网。Linux需安装Node.js **22.18+**与npm，执行 `sh start.sh`；Windows捆绑的node.exe不能在Linux使用。随后打开 `http://localhost:3001/`。启动文件会准备缺失的依赖和构建文件，运行服务时保持启动进程打开。

浏览器首次显示三步安装指引：

1. 明确二选一：**本地数据库**或 **MySQL 数据库**。SQLite 不需要任何数据库服务；MySQL 需要现有的 MySQL 8 服务和有建库权限的连接账号。
2. 选择本机/服务器访问、工作台名称与主题。
3. 创建主管理员用户名与至少十字符的密码，可勾选填充完整范例；默认不勾选。

本地库在 `data/worldloom.sqlite`，上传图片在 `data/uploads`，主管理员与安装配置在 `data/installation.json`，其他用户及权限在 `data/users.json`。安装目录必须可写。不要把 `data`、`.env`、`mysql.txt` 放进发布包或公开静态目录。SQLite 使用 Node 内置 `node:sqlite`，Node 22.18 仍会提示该 API 为实验功能；本版本已验证事务、重启读取和修订冲突，尚未在 Linux 实机执行。

## MySQL 的新库约束

全新安装先查询所选库名是否存在，再用 **CREATE DATABASE，不带 IF NOT EXISTS** 新建，成功后才迁移。新库使用 `chronicle_cartarium_` 前缀，旧 `worldloom_` 前缀继续兼容。已存在则拒绝，不覆盖、清理或迁移其他数据库。建库之后若迁移失败，保留这个新库供排查，不擅自删除；重试时可选择另一个新名称。安装账号需创建库及表的权限；完成部署后管理员可给运行账号缩小权限并在停机状态更新私有配置。

已有机器 `.env` 中明确配置的项目专用库属于升级路径：安装向导会标明并继续使用该库，保留内容。不要把 `.env` 改为默认库。本地模式与 MySQL 模式在首次安装时选定；后台目前不提供在线换库或自动迁移。

## Linux 服务器与 Windows 服务器

启动程序共用 Node，不依赖 PowerShell、盘符或 Windows 服务。未设置安装授权码时，服务默认先监听 `127.0.0.1`；首次安装必须在服务器本机访问 `localhost`，或使用 SSH 隧道：

```sh
ssh -L 3001:127.0.0.1:3001 user@server
```

随后在自己电脑打开 `http://localhost:3001/`。安装选服务器模式后，程序会自动改为监听 `0.0.0.0`；后台修改访问方式在下次启动生效。`HOST` 环境变量如果显式设置则优先，不要误把 `HOST=127.0.0.1` 留在需要外部访问的部署中。

公网部署使用 HTTPS 反向代理，代理必须保留 Host；将 `COOKIE_SECURE=true`，仅在确实有一个受信代理时设置 `TRUST_PROXY=true`。直接 HTTP 只适合本机和可信局域网。首次安装阶段拒绝非 localhost Host，即使反代连接来自回环地址也不能远程抢占初始化账号。

端口通过 `PORT` 设置，数据路径通过 `DATA_DIR` 设置。主管理员后台支持主题、工作台名称、访问方式、改密与多用户管理。多用户默认关闭；开启后可创建普通/次级管理员。普通用户仅查看公开或明确授权的记录，创建、修改/删除自己或其他人的内容按模块及单独授权执行。次级管理员管理创作、用户与档案导出，不能世界CRUD、完整备份恢复、系统配置和初始化。

`data/users.json`保存用户密码哈希、权限及教学状态，为私有安装文件，不进入创作JSON/Markdown。完整迁机时必须保留installation.json、users.json、数据库及uploads；uploads/.owners.json是资源作者索引。权限与登录会话目前服务于一个Node进程，未实现多实例权限同步或实时协同编辑；不同用户保存依然使用工作区revision，冲突需显式处理。

长期Windows/Linux服务由服务管理器监督固定入口 `node scripts/launch.mjs`，工作目录为安装根，环境为 `NODE_ENV=production`；HTTPS参数按上文设置。首次启动将绝对DATA_DIR写入.worldloom/current.json，之后该指针优先；不要换发行目录默认data冒充原实例。直接API启动属于手动管理，仍有完整备份但后台程序更新需要启动器。Docker使用容器原入口，由宿主机维护，不在容器内套本机启动器。重启后重新登录，会话暂存内存最长十二小时。

## Docker

Dockerfile 使用非 root Node 用户；Compose 支持选择本地存储的应用容器，安装时也能连接你提供的 MySQL 服务。容器通过 `HOST=0.0.0.0` 开放端口，首次安装用至少24字符的 `CHRONICLE_CARTARIUM_SETUP_TOKEN` 保护；在私有 `.env` 设置它，安装最后一步输入相同授权码。Compose不捆绑MySQL服务：向导选择本地数据库即可使用容器数据卷，或选择MySQL连接自己的服务。完成后授权码不能再次安装或绕过登录。**当前没有 Docker 实机验证，首次安装推荐普通 Node 启动。** 不要声称镜像已完成生产验收。

## 备份、初始化与恢复

后台初始化需输入 **初始化全部创作数据**，并勾选或不勾选 **填充范例内容**（默认关闭）。先备份工作区与上传图片到 `data/backups/before-reset-*`，完成后再事务替换内容并清理已上传资源。备份失败不会执行替换；revision 不一致返回 409。账号、安装设置与备份保留，空白模式可直接创建首个世界。

工作台 JSON 备份可在设置恢复；自动备份中的 `worldloom-backup.json` 可直接在界面恢复，`workspace.json` 是包含 data/revision/mode 的服务器快照，供核对修订。空白工作台可先创建一个空世界，再在工作台设置恢复完整备份。图片必须同时恢复 `uploads`，仅恢复 JSON 不会恢复原图。

完整机器迁移优先创建并验证.ccbackup，在新目录执行恢复工具并采用新DATA_DIR。此私有包包含密码哈希/连接凭据，当前不加密，不能公开。MySQL只恢复到确认全新的chronicle_cartarium_项目库；需要建库权限，备份验证还需删除自身临时验证库的权限。源码恢复命令与固定指针采用方法见[更新指引](update-strategy.md)。仍可停机私密复制完整data和.env；运行中只拷SQLite主文件不保证包含WAL。

## 当前beta手动升级

本节用于从beta.4及更早版本第一次接入beta.5；beta.5之后兼容的同格式版本使用后台受签名更新入口。没有自动联网更新；在线发布源、跨格式迁移与平台实机矩阵仍待完成，见[更新与恢复指引](update-strategy.md)。

1. 所有用户保存并等到“所有更改已保存”，停止当前服务，确认进程已退出。记录实际DATA_DIR绝对路径、服务配置与现有版本。
2. 完整备份实际DATA_DIR、私有`.env`及服务配置；MySQL额外备份明确的项目专用库并验证。普通JSON不是账号、权限、图片和schema的完整备份。
3. 新程序解压到独立目录，保留旧版。配置新启动进程的DATA_DIR为原绝对路径并保留所需私有环境配置；不能使用新目录默认的空data，也不能删除仍被指向的旧数据目录。
4. 按发行说明检查程序/数据兼容性后启动。若显示首次安装向导，停止核对配置与路径，不能用重新安装掩盖数据目录错误。检查世界、地图、图片、账号权限及保存状态。
5. 无schema/格式变化且兼容时可停新版再用旧程序接同一数据；存在不兼容迁移时要恢复配套完整备份到新目标，不能让旧程序直接打开新schema。新版本已有写入后不得自动恢复升级前快照。

Windows本机使用新目录的start.cmd，服务器更新原服务的程序路径及固定DATA_DIR；Linux本机使用新目录的start.sh，服务器更新systemd启动位置并固定数据/config。服务实例身份与文件权限需核对，不批量结束所有Node进程。

当前Compose仍支持源码build；新增宿主机 `scripts/update-docker.mjs` 接收可信固定摘要镜像，自动识别原实例/持久卷、备份到宿主机、仅更新app、验证并在失败时恢复新目标。此入口尚未Docker实机验收，也没有公开镜像发布或OCI签名校验，仍属待验证实现。保留原项目名/卷/私有配置，不执行`down -v`；后续Compose操作采用生成的.worldloom/docker-update.json覆盖文件。主机命令被强行中断可能维持维护，需检查处理。

## 生产测试版边界

- 当前工作区仍是完整快照读写，大地图会有写入放大；并发冲突显式阻止覆盖，没有实时协作。
- 图片、地图源数据和生成配方持久化；生成画面在 Worker 派生。不会自动识别导入图片的地形。
- 本地数据库仍由单Node进程访问，可在该进程内使用多用户授权；数据库 API 为同步，超大工作区仍可能暂时占用服务线程。
- Linux 启动入口与路径设计已检查，但没有 Linux/HTTPS/Docker 的实机部署结果。Node、MySQL 与浏览器的本机验证结果见开发日志。
